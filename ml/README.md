# ML-инструменты: подбор баланса боссов (Optuna)

`ml/tune.py` ищет значения баланса (здоровье босса, темп боя, время оглушения, доля казни), при которых ИИ-бот выигрывает с нужной долей побед
и за нужное время. **Игру скрипт не меняет**: `data/balance.json` правится только вручную, после вашего одобрения.

## Установка (один раз)

```
py -3 -m venv ml/.venv
ml/.venv/Scripts/python -m pip install -r ml/requirements.txt      # Windows; на Linux/macOS: ml/.venv/bin/python
```

Нужны Python 3.10+ и Node 22+ (`npm ci` в корне). Видеокарта не требуется: бой считает ядро игры на процессоре.

## Запуск

```
ml/.venv/Scripts/python ml/tune.py --boss korne --target "skill0.6:winrate=0.55..0.65,time=80..120" --trials 50
```

- `--target` — «мастерство бота : метрика=от..до», несколько метрик через запятую, несколько целей через `;`.
  Метрики: `winrate` (доля побед 0..1), `time` (среднее время победного боя, с), `wipes` (доля обрывов нити), `dmg` (средний урон за бой).
  Пример: `"skill0.6:winrate=0.55..0.65,time=80..120;skill0.95:winrate=0.85..1"`.
- `--fights 40` — боёв на ячейку в каждой пробе (больше — точнее, но дольше); `--verify 120` — проверка лучшего набора на других зёрнах.
- `--space space.json` — свои границы множителей: `{"hp":[0.6,1.5],"pace":[0.7,1.4]}` (убранный ключ — параметр не меняется).
  Параметры: `hp` (здоровье босса), `pace` (темп: меньше — реже атакует), `stagger_t` (длительность оглушения), `exec_frac` (доля здоровья за казнь).
- `--dry-run` — только проверить цель и показать пространство поиска.

Как это устроено: для каждой пробы Optuna (TPE, зерно фиксировано) предлагает множители к значениям из `data/balance.json`;
скрипт пишет временный файл-переопределение и запускает `tools/bot/cli.ts table --json --balance <файл>`;
штраф = насколько доля побед и время вышли за границы цели (плюс небольшая плата за размер правок).

## Отчёт

`ml/reports/<босс>-<дата>/`:

| Файл | Что внутри |
|---|---|
| `report.md` | цель, лучший набор множителей, переопределение баланса, значения на лучшем наборе и на проверочных зёрнах |
| `best_balance.json` | переопределение в форме `data/balance.json` (только изменённые числа) |
| `trials.csv` | все пробы: штраф, параметры, измеренные метрики |
| `history.png`, `metrics.png`, `params.png` | ход подбора, метрики на фоне целевых полос, параметры против штрафа (matplotlib, без окон) |

Отчёты — рабочие файлы и в git не попадают (`ml/.gitignore`); осознанно выбранный отчёт можно добавить принудительно.

## Как применить результат

1. Посмотрите `report.md`, при сомнениях увеличьте `--fights` и перепроверьте: `npm run bot -- table --boss korne --skill 0.6 --fights 200 --balance ml/reports/<…>/best_balance.json`.
2. После одобрения перенесите значения из `best_balance.json` в `data/balance.json` вручную.
3. Золотые записи v1.8 привязаны к прежнему балансу и разойдутся — это ожидаемо; перезапишите их осознанно или оставьте прежний баланс для режима сравнения.

Совет: значения, подобранные «на ощущение» в игре с `?dev=1` (кнопка «Скопировать balance.json»), можно сразу проверить ботом: сохраните их в файл и передайте `npm run bot -- table --boss korne --skill 0.6 --fights 200 --balance файл.json` — форма совпадает с переопределением баланса (частичный набор допустим).

# Нейросеть-игрок (RL)

Обучение с подкреплением (PPO): нейросеть учится побеждать боссов в бою на ядре игры. Симуляция идёт на процессоре
(Node, `worker_threads`, до ~16 потоков), сеть и обновления — на видеокарте NVIDIA (проверено на RTX 5080, Blackwell, sm_120).
Обученную политику можно экспортировать в JSON и пустить играть в настоящую игру (`?agent=…`). Игру и ядро это не меняет
(в `src/core/session.ts` добавлен необязательный крючок `tickHook`, без него поведение прежнее).

## Установка (один раз)

```
py -3.13 -m venv ml/.venv-rl
ml/.venv-rl/Scripts/python -m pip install torch --index-url https://download.pytorch.org/whl/cu128   # CUDA 12.8+; для RTX 50xx нужен именно cu128 или новее
ml/.venv-rl/Scripts/python -m pip install numpy
ml/.venv-rl/Scripts/python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_arch_list())"   # True и в списке sm_120
```

Нужны Node 22+ (`npm ci` в корне) и драйвер NVIDIA (на машине проверки — 617.42). `ml/.venv-rl/` в git не попадает.

## Как это устроено

| Часть | Файл | Что делает |
|---|---|---|
| Наблюдение и действия | `src/agent/obs.ts`, `src/agent/actions.ts` | вектор из 406 признаков (герой, босс и его состояние/фаза, ближайшие 8 снарядов с телеграфами, стены/пол, фаза «Пропустите!»); 5 дискретных «голов»: движение, вертикаль (вверх/вниз: удар вверх/вниз, прицел бомбы), прыжок, рывок, действие (удар / отбив-лечение / дымовая бомба). Решение раз в 4 тика (15 в секунду), кнопки удерживаются, нажатия — «тычком» в первом тике |
| Среда боя | `tools/rl/env.ts`, `worker.ts`, `server.ts` | один бой героя с боссом, награда настраивается (`--reward '{"hurt":1.0}'`), мир виден с задержкой реакции (`--lag`, в решениях); сервер держит N боёв в потоках и говорит с Python бинарным протоколом по stdio (float32, общая память между потоками) |
| Обучение | `ml/rl/train.py`, `model.py`, `envclient.py` | PPO: Actor-Critic MLP 2×256 (tanh), нормализация наблюдений и наград, GAE, мини-батчи, несколько эпох; инференс пачкой и обновления на GPU |
| Панель | `ml/rl/panel.py`, `ml/rl/panel/index.html` | графики вживую (SSE), таблица оценок против бота, «Агент играет» в настоящей игре (iframe с `?watch=`), кнопка гонки двух агентов |
| Оценка | `ml/rl/evaluate.py`, `tools/rl/agent-eval.ts` | нейросеть против бота на тех же зёрнах (таблица, интервалы Уилсона и бутстрэп); TS-версия считает тем же кодом, что работает в браузере |
| Экспорт | `ml/rl/export.py` → `public/agents/*.json` (только локально: папка в .gitignore, на сайт и в git веса не попадают) | веса и нормализация в компактном JSON (пак: модели по боссам + характеры) |
| Агент в игре | `src/agent/agent.ts`, `policy.ts`, `src/app/agent.ts` | инференс без библиотек, источник ввода вместо клавиатуры: `?agent=<пак>&persona=<характер>` |

Награда по умолчанию (`tools/rl/env.ts`, `DEFAULT_REWARD`): урон боссу (10 за весь запас здоровья), штраф за потерянное здоровье героя (0.7), победа +6,
поражение −2, таймаут −1.5, штраф за время (0.0008 за решение), штраф за смену действия (0.0004 — «дрожащий» ввод), потенциал сближения с боссом (0.25 на 500 px),
отбив +0.15, бросок бомбы +0.05. Эпизод — один бой на своём зерне (разные зёрна в каждом бою и в каждой среде).
Тайм-аут боя в обучении — `--max-sec` (150 с игрового времени). Таймаут считается концом эпизода (значение в конце не бутстрэпится).

## Запуск

```
# обучение (фоном; логи в ml/rl/runs/<имя>/metrics.jsonl, чекпоинты в ckpt/, показательные бои в demos/)
ml/.venv-rl/Scripts/python ml/rl/train.py --name misha-avg --boss misha --persona average --envs 128 --workers 12 --minutes 60
#   --resume            продолжить с ckpt/last.pt          --stop-win 0.6   остановиться, когда доля побед за 300 боёв ≥ 0.6
#   --steps 1e8         предел по шагам                     --reward '{"hurt":1.2}'  свои веса награды
#   --lag 3             задержка восприятия в решениях      --eval-every 60  как часто показательный бой и оценка (с)

# панель (http://localhost:8765): графики, «Агент играет», гонка двух агентов. Игру отдаёт из dist/ — сначала npm run build
ml/.venv-rl/Scripts/python ml/rl/panel.py

# оценка против бота (таблица в ml/rl/runs/<имя>/eval-*.md); температура/«липкость» — характер игрока
ml/.venv-rl/Scripts/python ml/rl/evaluate.py --run misha-avg --ckpt best --fights 200 --temp 1.0

# экспорт в игру и проверка тем же кодом, что в браузере
ml/.venv-rl/Scripts/python ml/rl/export.py --name tkachi --out public/agents/tkachi.json misha=misha-avg vladik=vladik-avg tima=tima-avg korne=korne-avg
npm run rl:eval -- --pack public/agents/tkachi.json --boss misha --persona average --fights 200 --skill 0.6
```

Остановить обучение: создать файл `ml/rl/runs/<имя>/stop`. Показательный бой «прямо сейчас» — кнопка в панели (файл `demo_now`).
Сервер среды можно запустить отдельно: `npm run rl:env -- --boss misha --envs 64 --workers 12` (протокол — в шапке `tools/rl/server.ts`).

## Как смотреть

1. `npm run build` (панель показывает настоящую игру из `dist/`), затем `ml/rl/panel.py` и откройте http://localhost:8765/.
2. Справа окно «Агент играет»: каждые `--eval-every` секунд обучение играет бой текущей политикой и пишет запись `.ttrec`; панель проигрывает её тем же движком игры
   (`?watch=`). Кнопки: последний бой, лучший бой за обучение, лучший из круга, «показательный бой сейчас». Бой идёт со скоростью игры (запись воспроизводится, а не транслируется).
3. Записи боёв лежат в `ml/rl/runs/<имя>/demos/*.ttrec`; любую можно открыть и вне панели: `npm run bot -- watch файл.ttrec`.

## Агент в настоящей игре

`?agent=tkachi&persona=careful` — вместо клавиатуры играет нейросеть (пак из `agents/tkachi.json` рядом с игрой или полный адрес JSON). Параметры:
`persona` (`average`, `careful`, `aggressive`, `novice` — из `ml/rl/personas.json`: температура выбора действия, «липкость» (шанс повторить прошлое действие),
минимальный промежуток между ударами и задержка реакции), `atemp` (своя температура), `aseed` (зерно «характера»), `aname` (имя игрока в гонке).
Агент детерминирован: то же зерно мира, модель, характер и `aseed` — тот же ввод. Играет в босс-тесте и на аренах боссов; вне арены (бег по «Тропе»)
он стоит: дистанции модель не учили, поэтому «Тропа целиком» агентам недоступна.

### Гонка двух нейросетей (панель, кнопка «Запустить гонку двух агентов»)

Полная «Гонка Ткачей» в дисциплине «Босс-раш» (Корнематка → Миша → Владик → Тима; для неё в организаторе включена дисциплина `boss`, `src/net/racecommon.ts`)
на локальном PeerJS (`tools/rl/peer-server.mjs`, порт 9166, поднимает панель). Страница панели сама открывает четыре окна (iframe):
организатор-автомат (`?race=org&orgauto=1&disc=boss`: выбирает дисциплину, стартует, когда готовы двое, шлёт состояние панели, выполняет «Ещё гонка»),
два игрока (`?race=play&room=КОД&agent=tkachi&persona=…&aname=…`: сами входят и нажимают «Готов») и обсервер (`?race=watch&room=КОД&stream=1`, крупно: две половины, табло, лента).
Каждое окно — на своём порту панели (8766–8769): у браузера своё хранилище для каждого. У каждой гонки свой `rid`, поэтому несколько страниц/браузеров не мешают друг другу.
Под обсервером — диагностика по шагам; если шаг висит дольше 25 с, окна перезапускаются сами (до 3 раз). Окна участников нельзя прокручивать за экран: Chrome замедляет невидимые окна.
Без панели: организатор `?race=org&orgauto=1`, игроки и обсервер по ссылкам выше (`&peer=localhost:9166`); гонка 1×1: `?race=duel&agent=tkachi&persona=…&arole=host|guest`.
Тест: `tests/e2e/agents.spec.ts` (под мьютексом `C:	t-e2e.lock`, `PW_PORT` — свой порт предпросмотра).
