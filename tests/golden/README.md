# Золотые записи v1.8

Текущие исправления боя описаны в `docs/COMBAT_FOUNDATION.md`. Исходные файлы
v1.8 сохранены для `legacy/`; в `current/` лежат отдельные ожидания нового ядра
для трёх записей с изменённым сбросом действий при возрождении. Они привязаны
к SHA-256 оригинала и не меняют его ввод. Проверка текущего ядра: `npm test`.

Эталон поведения игры для проверки переноса ядра на v2.0 (`docs/V2_PLAN.md`, раздел 4). Каждая запись — журнал ввода по тикам (RLE; один тик = 1/60 с),
зерно ГСЧ, режим сцены и **ожидаемый исход**. Проверка: `npm run golden` (воспроизводит на текущей сборке и сравнивает исход);
перезапись эталона (только осознанно, на заморожённой сборке): `npm run golden:record`.

## Формат
`{ name, kind, version, seed, expect, journal }` (`race-b1`: `{ expectOrg, players:[{ name, journal, expect, stats }] }`).
`journal`: `{ v, mem, ver, cat, seed, segs:[{ seed, np, hv, data:{ players, mode, boss, camp }, n, rle:[значение, повторов, …], acts:[[тик, имя, a, b, c]…], chk:[тик, хэш, …] }], splits, pauses, race }`.
Значение тика в `rle` = ввод игрока 1 (`raw | pend<<10`, 17 бит); у двух игроков ввод игрока 2 добавлен старшими разрядами (`× 131072`).
Биты `raw`: left, right, up, down, jump, atk, dash, heal, bomb, tool; биты `pend` (фронты нажатий): jumpP, atkP, dashP, healP, upP, bombP, toolP.
`hv: 2` — богатый хэш (`Journal.hash2`: игроки, босс, враги, снаряды, бусины, смерти) каждые 300 тиков в `chk`.

## Действия `acts` («ex» — отладочные команды записи)
Ввода бывает недостаточно, чтобы быстро дойти до нужной сцены, поэтому в журнал пишутся действия (их обязано воспроизвести любое ядро, поэтому они часть формата):

| id | Что делает | Где используется |
|---|---|---|
| `ex 10` | герои у арены Корнематки, двойной прыжок, точка возрождения у входа | `boss-korne-*` |
| `ex 11` | выдать двойной прыжок (как подобранный предмет) | `chapter1-full` |
| `ex 20 x y` | перенос героя в пиксели (x, y), скорость 0 (бегун застрял) | коридоры, глава I |
| `ex 1` | довести босса до последнего удара и ударить | `race-b1` |
| `ex 2` | перенос героя на выход этапа | `race-b1` |
| `rel` | «пошёл» в гонке: герой отпущен, IGT с нуля | `race-b1` |
| `T`, `bc`, `br`, `so`, `sc`, `sb`, `mo`, `mc`, `mm`, `mg`, `tp` | пауза, меню скамьи, лавка, карта, техпауза | см. `src/journal.js` |

## Записи для проверки переноса ядра (этап 2 v2)
Бот проходит лишь часть игры, поэтому к исходным записям добавлены записи, снятые со **старой игры v1.8** (`legacy/tools/golden.js record`):

| Запись | Что | Зачем |
|---|---|---|
| `fuzz-<босс>-0…4`, `fuzz-level-*`, `fuzz-road2…4-*` | случайный ввод всех кнопок 3200–3600 тиков, у каждой записи своё снаряжение (`loadout`: оружие, инструмент, до двух оберегов) | оружие, заряд, инструменты, обереги, статусы, все враги, смерти и возрождение, колючки, хват, планер |
| `fuzz-coop-vladik/tima` | то же, два игрока | кокон, подъём, поводок |
| `fuzz-heart-*` | оберег «Паучье сердце» + булава + крюк | пересчёт здоровья |
| `ui-level1`, `ui-road2`, `ui-road4` | телепорты к скамьям, меню скамьи, покупки, карта и быстрый переход, подбор предмета способности | лавка, карта, сохранение |

Поле `loadout` записи — содержимое `tt_loadout` на время проверки (в старой игре его кладут в localStorage, в ядре v2 оно уходит в `loadoutSave`).
Дополнительное действие `ex 12` — выдать 70 бусин (чтобы быстро покупать в лавке).

## Записи v2 (`tests/golden/v2`)
В кампании и везде теперь бои с боссами на данных (`penitent`, `misha2`, `vladik2`, `tima2`), поэтому записи боёв, коопа, Босс-раша, главы I и гонки
сняты заново **ядром v2** (`npm run golden:record`, гонка — `npm run golden:race`) и лежат в `tests/golden/v2/`: `boss-<id>-win / -lose`, `fuzz-<id>-0…4`,
`fuzz-coop-vladik2/tima2`, `fuzz-heart-penitent/tima2`, `chapter1-full`, `coop-two-bots`, `speedrun-boss-rush`, `race-b1`.
Каждую запись рекордер перед записью проверяет воспроизведением. Победы проходит безошибочный бот (`NoHitPilot`), остальное — `Brain`.
Записи v1.8 в `tests/golden/` (коридоры `road-ch*`, `fuzz-level-*`, `fuzz-road*`, `ui-*`, `race-b1`) остались: их читает и старая игра (`legacy-golden`), в них нет боя со старыми боссами.

## Как проверять
- v2: `npm test` (файл `tests/unit/golden.test.ts`) — каждая запись воспроизводится ядром в тот же исход и по пути сверяются контрольные хэши.
- v1.8: `npm run legacy:golden`.
- Если запись разошлась: `legacy/tools/trace.js <имя>` снимает трассу старой игры по тикам (`tests/trace/`), затем
  `TRACE=<имя> npx vitest run tests/unit/trace.test.ts` показывает первый тик и поле, на котором ядро v2 отличается.
