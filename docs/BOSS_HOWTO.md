# Как добавить босса за 15 минут

Инструкция для тех, кто делает боссов параллельно (волна 0 каркаса). Главное правило: **босс = новые файлы, общие файлы не правятся** — тогда две ветки с двумя боссами сливаются без конфликтов. Формат данных — `docs/BOSS_DATA.md`, правила честности — `docs/BOSS_FAIRNESS.md`, замысел — `docs/BOSS_DESIGN.md`.

## 0. Подготовка (1 минута)

```
git fetch origin && git merge origin/main
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install
```

Свои файлы босса `<id>` (латиница и `_`, например `weaver_queen`):

| Файл | Зачем | Обязателен |
|---|---|---|
| `data/bosses/<id>.json` | всё, что делает босс: атаки, связки, фазы, арена, существа | да |
| `src/core/boss/kinds/<id>.ts` | особая логика, которую не выразить данными (хуки, `attack.fx`) | нет |
| `src/view/draw/boss/<id>.ts` | рисунок тела, форм и существ | нет |
| `tests/unit/boss-<id>.test.ts` | ваши тесты | рекомендуется |
| `data/bosses/<id>_<часть>.json` с `"hidden": true` | второй и третий босс дирижёра | только для боя нескольких боссов |

**Не трогать** (так конфликты исключены): `src/core/boss/registry.ts`, `catalog.ts`, `schema.ts`, `exec.ts`, `src/ui/menus.tsx`, `src/core/duel.ts`, `tools/**`, `data/bosses/rules.json`. Если без правки общего файла никак (нужна новая возможность каркаса), не правьте его молча: напишите автору волны 0 — иначе два агента придумают две несовместимые правки.

## 2. Посмотреть (2 минуты)

- Браузер: `npm run dev`, адрес `http://localhost:5173/?dev=1` → «Босс-тест» → карточка вашего босса (название, ориентир, арена, рекорд). Включите «Тренировку» (клавиша `T`): видно название и кадры текущего телеграфа, `P` — фаза старта, `Y` — сброс боя.
- Node без браузера: `npm run sim -- --boss <id> --frames 36000 [--seed 1]` — бой случайным вводом, печатает итог и скорость.

## 3. Добавить возможности по списку (5 минут, по необходимости)

| Нужно | Что писать в JSON | Раздел `BOSS_DATA.md` |
|---|---|---|
| Фаза с превращением, сценой, надписью, звуком, камерой | `phases[n].scene`, `form`, `silent`, `enterChain` | Сцены и трансформация |
| Летающий босс, другой размер тела, другой набор приёмов | `form.fly`, `form.size`, `form.attacks`, `form.policy` | Сцены и трансформация |
| Неподвижный босс (турель, голова на стене) | `still: true`, `place`, `antiCheese.relocateChain` (**обязательно**) | Неподвижные боссы |
| Уязвимые точки, броня остального тела | `weak` (или `form.weak`) с окнами `open` | Неподвижные боссы |
| Приспешники, которые появляются и исчезают | `creatures`, `attack.summon` | Существа-приспешники |
| Платформы, лучи, зоны урона, барьеры, точки появления | `arena: { level, ents }`, `attack.fire` | Сущности арены |
| 2–3 босса в бою, общее или раздельное здоровье, эстафета | `conductor` + отдельные `hidden`-файлы участников | Несколько боссов |
| Что-то, чего данные не умеют | `kinds/<id>.ts` (`frame`, `onPhase`, `onAttack`, `onDeath`, `fx`, `allow`) | Особая логика |
| Свой вид | `src/view/draw/boss/<id>.ts` (`base`, имя формы, `'creature:<id>'`) | Автообнаружение |

Живые образцы каждой возможности (рабочие и честные) — `tests/fixtures/bosses.ts`: `morphBoss`, `silentBoss`, `arenaBoss`, `trioBosses`, `stillBoss`; их можно копировать в JSON.

## 4. Проверить (4 минуты) — чек-лист для PR

Выполняйте по порядку, каждый шаг должен пройти без ошибок. Предупреждения (жёлтые) допустимы, если вы понимаете причину — запишите её в описание PR.

1. **Валидатор**: `npm run boss:check -- --boss <id> --frames`. Ошибок нет. Частые ошибки:
   - `замах N кадров короче нормы` — минимум `parry` 20, `dodge` 24, `unblockable` 30 (и для зон арены, и для существ);
   - `no-escape` — удар по площади, от которого не уйти ни бегом, ни рывком, ни прыжком за время замаха: сузьте коробку или удлините замах;
   - `react`, `gap-short`, `chain-punish`, `pause`, `rest`, `flux` — паузы и поток урона (см. `BOSS_FAIRNESS.md`);
   - `still-relocate` — неподвижному боссу нужна `relocateChain`, накрывающая героя там, где он стоит (`from: "target"` или `fire`);
   - `weak-short` / `weak-unreachable` — точка открывается слишком коротко или только во время атак, которых нет в связках;
   - `beam-no-safe` — зоны урона закрывают весь пол и платформы; `plat-hide-warn` — платформа исчезает без предупреждения ≥ 30 кадров;
   - `cond-no-window` / `cond-flux` — у боя нескольких боссов нет паузы без атак или слишком густой поток урона;
   - ошибки загрузки («нет связки», «неизвестное существо», «сцена длиннее нормы», «площадка кратна тайлу 32») поднимаются сразу при запуске игры/тестов с адресом поля.
2. **No-hit бот**: `npm run boss:nohit -- --boss <id> --runs 20`. Каждая связка каждой фазы, каждый переход в новую фазу (со сценой) и — у дирижёра — бой целиком проходимы без урона (`да`), бои безупречно выигрываются (`убит босс: N/N`). Строка `НЕТ` называет кадр, положение героя и атаку, где выхода нет. Для боссов с уязвимыми точками и неподвижных бот бьёт только открытые точки; если бот не успевает убить босса за лимит, окна слишком короткие или точка недосягаема с земли.
3. **Эксплойты**: `npm run boss:cheese -- --boss <id>`. «Проходит»: ни один бот (хаг, угол, цепочка оглушений, спам отбива, спам иглы, рывки сквозь тело, отсидка у дальней стены, насест на платформе) не убивает босса быстро и дёшево и не живёт «бесконечно». Нарушение чинится данными: `antiCheese` (отгон, перемещение, пороги), атаками, которые достают насест, и окнами.
4. **Тесты**: положите `tests/unit/boss-<id>.test.ts` (шаблон ниже). Все `data/bosses/*.json` и без вашего теста проверяются в `boss-schema`, `boss-validate`, `boss-nohit` (проходимость связок и безупречный бой).
5. **Общая проверка**: `npm run lint && npm run typecheck && npm test && npm run build` (e2e идёт в CI). Тесты занимают около двух минут: во время работы запускайте точечно — `npx vitest run tests/unit/boss-<id>.test.ts`.

Шаблон теста (`tests/unit/boss-<id>.test.ts`):

```ts
import { describe, expect, it } from 'vitest';
import { bossDef } from '../../src/core/boss/registry';
import { dstate } from '../../src/core/boss/exec';
import { feedInput, makeFuzzer } from '../../src/core/fuzzinput';
import { World } from '../../src/core/world';

describe('мой босс', () => {
  it('загружен и в мире есть босс с нужным телом', () => {
    expect(bossDef('my_boss')).toBeTruthy();
    const w = new World({ seed: 1, mode: 'bosstest', boss: 'my_boss', players: 1 });
    expect(w.bosses).toHaveLength(1);
  });
  it('детерминизм: то же зерно и ввод — то же состояние', () => {
    const run = (): string => {
      const w = new World({ seed: 5, mode: 'bosstest', boss: 'my_boss', players: 1 });
      const fz = makeFuzzer(w, 5);
      for (let i = 0; i < 3000; i++) { feedInput(w, [fz(0)]); w.tick(); }
      return JSON.stringify([w.players.map((p) => [p.x, p.hp]), w.bosses.map((b) => [b.x, b.hp, dstate(b).mem.hist])]);
    };
    expect(run()).toBe(run());
  });
  // ваши проверки особых кадров: фаза, сцена, окна точек, расписание арены — образцы в tests/unit/boss-scene.test.ts,
  // boss-arena.test.ts, boss-still.test.ts, boss-conductor.test.ts
});
```

## 5. Правила (чтобы код прошёл ревью)

- **Числа боя — только в данных.** Кадры (60/с), пиксели (тайл 32), в коде босса магических чисел нет.
- **Детерминизм.** В `src/core/**` нельзя `Math.random`, `Date`, `performance`, таймеры браузера (линтер запрещает); случайность — только `sc.rBoss` / `sc.rngFor('имя')`, отложенные действия — счётчики кадров (не `sc.after` без нужды и не `delayedCall`). Хук `kinds` получает `k.rng`.
- **Время в хуках и данных — кадры исполнителя**: замедление и оглушение босса уже учтены.
- **Телеграф — закон.** Цвет замаха = тип удара (`yellow` — отбить, `red` — только уворот, `purple` — не отбивается, `white` — нейтральный). Одинаковые цвет+звук+поза у разных приёмов — осознанная «обманка» (валидатор предупредит `cue-dup`).
- **Рисунок не заменяет телеграф**: контур замаха, места ударов, окно наказания и уязвимые точки рисует общий код поверх любого тела.
- **Файлы `kinds/<id>.ts`**: модули исполнителя, мира и урона — только `import type` (иначе цикл при загрузке; правило ESLint это проверит). Нужное приходит через `KindApi`.
- **Сеть**: боссы на данных по сети пока не поддержаны (кнопка «по сети» у них отключена); дуэль — флаг `duel: true` пока не включайте (запуск раунда — волна 1).
- **Арена**: платформы и барьеры кратны 32 px; координаты — от левой стены и от пола вверх (см. `BOSS_DATA.md`). Сначала нарисуйте на бумаге размеры: арена `vladik` — 1344 × 448 px внутри, пол на 18 тайле, настоящие платформы на высоте 96 px.

## 6. Если что-то не работает

| Симптом | Причина |
|---|---|
| Карточки нет | у босса `dev: true` (нужен `?dev=1`) или `hidden: true`; либо файл не в `data/bosses/` или с ошибкой (ошибка схемы пишется в консоль/вывод тестов сразу при загрузке) |
| «босс не по схеме: …» | поле не по схеме; схема строгая, лишние поля запрещены — смотрите путь в сообщении |
| Босс стоит столбом | политика/набор приёмов не оставляют допустимых связок (проверьте `requires.dist` первых шагов, `form.attacks`, `cooldown`) |
| Герой «залипает» в платформе | твёрдая платформа ждёт, пока место освободится — это нормально; проверьте `pend` в `sc.arena` |
| `boss:nohit` бесконечно долго | много сущностей арены и существ; уменьшите `--runs`, используйте `--scan-only` |
| В Node-инструментах нет вашего `kinds`/босса | файл должен называться `<id>.ts` / `<id>.json`, `default`-экспорт у `kinds`; для `boss:*` запускайте через `npm run` (там включён загрузчик уровней) |
