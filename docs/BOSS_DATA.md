# Данные боссов (каркас 2.5)

Босс на данных — это один JSON в `data/bosses/` (схема на zod: `src/core/boss/schema.ts`) плюс общий исполнитель в ядре (`src/core/boss/exec.ts`). Ни одного числа боя в коде нет: замахи, удары, снаряды, движение, связки и фазы лежат в файле. Старые боссы (Корнематка, Миша, Владик, Тима) пока остаются ручными автоматами; их перенос на каркас — версия 2.6. Волна 0 (подготовка к параллельной разработке боссов 2.6+) добавила автообнаружение боссов, сцены и трансформацию, неподвижных боссов с уязвимыми точками, существ, сущности арены и дирижёра нескольких боссов — разделы ниже; **пошаговая инструкция «как добавить босса за 15 минут» — `docs/BOSS_HOWTO.md`**.

Единицы: **время — в кадрах** (60 в секунду), расстояния — в пикселях мира (тайл = 32 px), углы — в градусах.

## Как посмотреть манекена

`?dev=1` в адресе → «Босс-тест» → карточка «Манекен-наставник (dev)». Рекомендуется включить «Тренировку» (клавиша T): видно название последнего телеграфа и счётчик урона, фаза старта выбирается клавишей P. В Node: `npm run sim -- --boss dummy --frames 36000`. По сети манекен не поддержан.

## Язык атаки (`Attack`)

```
id, name?                    — идентификатор и название для тренировки
tell:     { frames, cue: { color, sfx, pose }, lockFace? }          — замах
active:   [{ from, to, hit: Box, dmg, kind, knock? }]               — удары (кадры от конца замаха, включительно)
move:     [{ from, to, vx, vy, toward }]                            — движение босса
spawn:    [{ at, proj, kind, from, ox, oy, vx, vy, aim, count, spread, dmg? }]   — снаряды
recovery: { frames, punishWindow: { from, to } }                    — восстановление и окно наказания
requires: { dist?, phase?, arenaSide?, hpBelow? }                   — условия, при которых атаку можно начинать
summon:   [{ at, creature, ox, oy, count }]                         — призыв существ (раздел creatures)
fire:     [{ at, ent }]                                             — запуск сущности арены (раздел arena)
fx:       [{ at, name, args }]                                      — особый эффект из kinds/<id>.ts
```

Порядок кадров: **замах** (`tell.frames`) → **рабочая часть** (кадры `0…E`, где `E` — последний из `active.to`, `move.to`, `spawn.at`) → **восстановление** (`recovery.frames`). Урон наносится только в кадрах `active`, снаряды появляются в кадр `spawn.at`.

- **`tell.cue.color`**: `yellow` — парируемое, `red` — только уворот, `purple` — неотбиваемое, `white` — нейтральный замах (в играх лучших боссов одинаковый замах у разных приёмов — осознанная «обманка»). Цвет определяет контур тела и мигание в замахе (вид: `drawDataBoss`). `sfx` — имя звука, `pose` — имя позы (для арта босса). `lockFace`: взгляд фиксируется в начале замаха, иначе босс следит за героем до конца замаха, а к первому активному кадру разворот фиксируется.
- **`kind`** (тип удара, `HitKind`): `parry` — можно отбить; `dodge` — только уворот; `unblockable` — не отбивается и не гасится рывком, только избежать. Он идёт в `hurtPlayer(sc, p, dmg, srcX, spike, hk)` и в снаряды (`Proj.hk`). Что делает с типом удара герой (идеальный отбив, цвета) — логика Парирования 2.0, каркас лишь проставляет `hk`.
- **`Box`**: `{ x, y, w, h, at }`. `at: "self"` (по умолчанию) — `x` отсчитывается от центра босса *вперёд* (зеркалится по взгляду; левый край при взгляде влево — `центр − x − w`), `y` — от верха босса. `at: "target"` — от центра ближайшего героя на момент конца замаха (удар «в место, где стоял герой»), без зеркала.
- **`knock`**: `{ vx, vy }` — отброс героя, если удар попал: `vx` направлен от босса.
- **`move`**: `toward: "player"` — знак `vx` относительно направления на героя (направление берётся в первый кадр отрезка); `"facing"` — направление, зафиксированное замахом (`commitFrames`), поэтому перебежка за спину не разворачивает выпад; `"wall"` — к ближайшей к боссу стене; `"fixed"` — `vx` в мировых осях. Ненулевой `vy` в первый кадр отрезка задаёт импульс (прыжок); гравитация — всегда. Вне отрезков на земле `vx = 0`.
- **`spawn`**: `proj` — `{ kind, w, h, life }` (`kind` — вид снаряда из `src/content/projectiles` с `data: true`: `spore` — дуга под гравитацией, `wave` — прямо по горизонтали до стены, `rock` — падающий камень, `note` и `glob` — дуги; новый вид — новый файл, см. `docs/CONTENT_HOWTO.md`; `life` в кадрах); `kind` — тип удара снаряда; `from: "self"` — от центра босса (`ox` вперёд, `oy` по высоте), `"target"` — от точки героя (`oy: -300` — камень сверху над ним); `vx` зеркалится по взгляду для `self`; `aim: true` — целиться в героя (длина скорости `hypot(vx, vy)`); `count` и `spread` — веер из `count` снарядов с углом `spread` между соседними; `dmg` — урон снаряда (по умолчанию 1, у тяжёлых видов — `heavy: true` в описании снаряда — 2). Место появления сдвигается вниз, если оказалось в стене.
- **`recovery.punishWindow`**: кадры восстановления (с нуля), в которые босс беззащитен для серии ударов; в них `DState.punish = true` (зелёное кольцо у ног манекена, бот и тесты используют флаг).

### Правила честности (`data/bosses/rules.json`)

Загрузка босса отклоняется, если нарушены минимумы: замах не короче `minTellFrames` для самого строгого типа удара атаки (`parry` 20, `dodge` 24, `unblockable` 30), восстановление не короче `minRecoveryFrames`, окно наказания не короче `minPunishFrames` и целиком внутри восстановления; кроме того проверяются ссылки (атака, связка, `enterChain`), порядок порогов фаз, `from ≤ to` и пустые атаки.

## Связки и политика

```
Chain:  { id, steps: [{ attack, gapFrames? }], weight, requires?, cooldown? }
Policy: { chains: [id…], noRepeat, fatigue?, restFrames: [min, max], priority: [{ chain, closeDist, closeFrames }] }
```

- `gapFrames` — пауза после шага до следующего замаха (по умолчанию — всё восстановление шага); так делаются быстрые комбо. У последнего шага работает полное восстановление и окно наказания.
- **Выбор** (`policy.ts`, `pickChain`): ровно одно обращение к `sc.rngFor('boss')` на выбор. Допустимы только связки из `policy.chains`, у которых выполнены `requires` связки и `requires` её первой атаки, нет перезарядки (`cooldown` кадров) и нет среди последних `noRepeat` выбранных. Если таких нет — `noRepeat` ослабляется (запрещена лишь самая последняя связка); если нет вообще никого, босс ждёт (**сухое правило**: недопустимая связка не выбирается ни при каком броске). `dist` проверяется только у первого шага связки.
- **`fatigue`**: вес связки умножается на `factor` за каждое недавнее использование; одно использование «забывается» за `decay` кадров.
- **`priority`** («отогнать»): если герой ближе `closeDist` px подряд `closeFrames` кадров (у стены — `cornerFrames`, если задан), выбирается связка `chain`, минуя веса (но с учётом её `requires` и перезарядки). Общий «отгон» и «перемещение» для всех боссов задаёт `antiCheese` (ниже), `priority` нужен для особых случаев.
- **`requires`**: `dist: [мин, макс]` (по горизонтали до ближайшего героя), `phase: [номера]`, `arenaSide: left|center|right` (треть арены, где стоит босс), `hpBelow` (доля здоровья).

## Фазы и босс

```
Phase:   { fromHp, rageFrames?, scene?, silent?, enterChain?, form?, policy }           (scene, silent, form — раздел «Сцены и трансформация»)
BossDef: { id, name, about, landmark?, tips?, dev?, hidden?, order?, duel?, arena (строка | { level, ents }), size, place?, still?, fly?, weak?,
           hp: [1 герой, 2 героя], color, music?, intro: { frames, say?, skippable?, events? }, deathFrames,
           idle: { walkSpeed, keepDist }, contact?: { dmg, kind }, attacks, chains, phases (1–3), creatures?, conductor?, antiCheese? }
```

Фаза включается, когда `hp / maxHp ≤ fromHp` (у первой — 1). Переход использует общие правила `bosses2.ts`: рёв, неуязвимость на `rageFrames`, сброс снарядов, отталкивание героев; затем пропускаемая вставка-сцена (`scene`, пропуск прыжком или ударом), затем **переходный приём** `enterChain` — обычная связка с телеграфом, потом политика новой фазы. Стойкость, оглушение (текущая атака обрывается), двойной урон по оглушённому и казнь работают как у остальных боссов; замедление растягивает время исполнителя (кадры идут реже). `arena` — id арены из `src/content/arenas` (сейчас `misha`, `vladik`, `tima`): уровень из `levels/tropa.ldtk` и точка появления босса. Новая арена — новый файл, см. `docs/CONTENT_HOWTO.md`.

## Состояние исполнителя

Лежит в `boss['d']` (`DState`, только данные): `mode` (`intro`, `idle`, `rage`, `scene`, `attack`, `dead`), `atk`, `af` (кадр атаки), `chain`, `step`, `punish`, `cue`, `mem` (история связок, перезарядки, усталость). `boss.state` для остального кода: `intro`, `idle`, `tell`, `active`, `recover`, `rage`, `dead`.

## Честность и защита от читов

Проверки и защита описаны в `docs/BOSS_FAIRNESS.md`; коротко:

- `npm run boss:check [-- --boss id] [--frames]` — валидатор честности (замах, окно наказания после связки, паузы, ответы на каждый тип удара, габариты в арене, поток урона за 3 с); `--frames` печатает таблицу кадровых данных. Все `data/bosses/*.json` проверяются в Vitest.
- `npm run boss:nohit -- --boss id --runs 50` — no-hit бот: каждая связка должна проходиться без урона; непроходимая связка валит тест.
- `antiCheese` у босса: `{ enabled?, shoveChain?, relocateChain?, shove?, stagger?, spam?, wallStun?, relocate? }`. Числа по умолчанию — `rules.json → antiCheese`, у босса они переопределяются частично; `enabled: false` выключает защиту, `wallStun: false` — только самооглушение от стены. `shoveChain` — связка-«отгон» (герой вплотную дольше 2,5 с, у стены 2,0 с), `relocateChain` — перемещающая (герой невредим рядом дольше 12 с).
- `npm run boss:cheese -- --boss id` — «злые» боты, таблица времени убийства и потерь до/после включения защиты.

## Автообнаружение боссов (волна 0)

Босс добавляется **только новыми файлами**, общих списков и `registerBoss(...)` в коде больше нет:

| Что | Где | Обязательно |
|---|---|---|
| Определение босса | `data/bosses/<id>.json` | да |
| Особая логика (хуки, особые эффекты атак) | `src/core/boss/kinds/<id>.ts`, `export default` объект `BossKind` | нет |
| Рисунок (тело, варианты тела, существа) | `src/view/draw/boss/<id>.ts`, `export default { base, <имя формы>, 'creature:<id>' }` | нет (без него рисуется универсальный «манекен») |

Файлы находят сами: в Vite и Vitest — `import.meta.glob` (`registry.ts`, `kinds.ts`, `view/draw/bossdraw.ts`), в Node-инструментах (`tsx`: `sim`, `bot`, `boss:check`, `boss:nohit`, `boss:cheese`) — чтением папок (`process.getBuiltinModule('node:fs')`) и динамическим `import()` для `kinds`. Никакой общий файл при добавлении босса не правится, поэтому два босса в двух ветках не конфликтуют при слиянии.

Из реестра строятся (`src/core/boss/catalog.ts`): **карточки Босс-теста** (название, ориентир `landmark`, арена, рекорд), список боссов для **гонок и ботов** (`raceBossIds`) и **дуэли** (`duelBossIds`), советы на экране «Как играть → Боссы» (`tips`).

Поля верхнего уровня, нужные для карточек:

| Поле | Значение |
|---|---|
| `landmark` | короткий ориентир под названием карточки («Глава V», «бей в светящуюся точку») |
| `dev` | `true` — карточка видна только по `?dev=1` (манекен; рабочие заготовки боссов) |
| `hidden` | `true` — служебный участник боя (второй босс дирижёра): карточки, гонок, дуэли и «Как играть» нет |
| `order` | порядок среди боссов на данных (меньше — раньше; по умолчанию 1000, дальше по `id`); dev-карточки всегда после обычных |
| `duel` | `true` — вносить в список дуэли. Запуск раунда дуэли для боссов на данных ещё не подключён (волна 1): валидатор предупредит |
| `tips` | список советов для «Как играть → Боссы» |

Раздел `arena` — либо строка с уровнем (`"vladik"`), либо объект `{ "level": "vladik", "ents": [...] }` с сущностями арены (см. ниже). Тестовые фикстуры волны 0 лежат в `tests/fixtures/bosses.ts`, в `data/bosses` их нет.

## Сцены и трансформация

```
Scene:  { frames, skippable = true, say?, events: [{ at, say?, sfx?, shake?: { ms, i }, flash?: { ms, r, g, b }, fade?: { out, ms }, zoom?: { k, frames }, morph? }] }
Phase:  { fromHp, rageFrames?, scene?: Scene, silent = false, enterChain?, form?: Form, policy }
Form:   { size?: { w, h }, fly?: { hover, speed = 120, bob = 0 } | false, still?, draw?, color?, attacks?: [id…], policy?, idle?, contact?: {…} | false, weak?: [Weak…] }
```

Порядок перехода в новую фазу: `rageFrames` (рёв, босс неуязвим) → **сцена** → тело `form` применяется (в кадр события `morph` или в конце сцены) → **переходный приём** `enterChain` с телеграфом → политика новой фазы.

- **Сцена не блокирует игру дольше нормы**: `rules.scene.maxFrames` (480 кадров = 8 с) для любой сцены, `maxUnskippableFrames` (120 кадров) для непропускаемой; исполнитель обрезает сцену по норме, валидатор и загрузка файла отвергают длиннее. Пропуск — прыжок или удар любого локального героя; недоигранное превращение (`morph`) в этот момент применяется, затемнение и зум камеры возвращаются. Во время сцены интерфейс рисует чёрные полосы и подсказку «Прыжок или удар — пропустить».
- **События сцены** (`at` — кадр от начала сцены): `say` — надпись, `sfx` — звук, `shake`/`flash`/`fade` — камера и экран, `zoom: { k, frames }` — приблизить камеру на `frames` кадров (`k` 0,66–1,6), `morph: true` — превратить тело именно сейчас. Те же `events` бывают у `intro` (`intro.skippable` по умолчанию `false`).
- **Фаза без рёва** (`silent: true`): нет вспышки, отброса героя и сброса снарядов, босс уязвим; переход — только `enterChain` (обязателен): «переходная атака с телеграфом вместо неотключаемого ролика». `rageFrames` у такой фазы игнорируется (предупреждение `silent-rage`); `scene` возможна — на время сцены босс неуязвим.
- **Тело `form`** накапливается по фазам: тело фазы n = базовое тело босса + формы фаз 1…n. Что меняется:
  - `size` — размер тела и хитбокса (центр и низ сохраняются; если новое тело оказалось в стене, оно поднимается);
  - `fly` — режим полёта: нет гравитации, низ тела держится на `hover` px над полом (`speed` — скорость выравнивания, `bob` — покачивание); `false` возвращает на землю. У приёмов летающего босса `move.vy` — **непрерывная** вертикальная скорость (пике), а не импульс прыжка; после приёма тело само возвращается на высоту;
  - `still` — неподвижное тело (см. ниже);
  - `attacks` — набор приёмов («набор состояний»): связка, чьи шаги не входят в набор, не выбирается;
  - `policy` — политика связок **этой** фазы вместо `phase.policy` (не накапливается);
  - `idle`, `contact`, `color`, `weak` — как у босса, заменяют прежние;
  - `draw` — имя варианта в `src/view/draw/boss/<id>.ts` (если нет — `base`, если и его нет — универсальный «манекен»).
- В `DState` добавлены `formPh` (фаза, чьё тело на боссе), `floor` (пол арены, px), `pin` (точка закрепления неподвижного).
- Тренировка «старт с фазы 2» сразу даёт тело фазы 2 и запускает сущности арены этой фазы.

```json
"phases": [
  { "fromHp": 1, "policy": { "chains": ["c_swing"], "noRepeat": 0, "restFrames": [30, 40] } },
  { "fromHp": 0.5, "rageFrames": 20,
    "scene": { "frames": 90, "skippable": true, "say": "Крылья!", "events": [
      { "at": 5, "shake": { "ms": 300, "i": 0.01 }, "sfx": "roar" },
      { "at": 40, "morph": true, "flash": { "ms": 200 } },
      { "at": 60, "zoom": { "k": 1.3, "frames": 20 }, "say": "Держись!" } ] },
    "form": { "size": { "w": 60, "h": 44 }, "fly": { "hover": 90, "speed": 160 }, "draw": "bat", "attacks": ["dive", "orb"] },
    "enterChain": "c_orb",
    "policy": { "chains": ["c_dive", "c_orb"], "noRepeat": 1, "restFrames": [30, 40] } }
]
```

## Неподвижные боссы и уязвимые точки

```
BossDef: still = false, place?: { x?: 0…1 (доля ширины арены), y?: px над полом }, weak: [Weak…]
Weak:    { id, box: { x, y, w, h }, mirror = false, open: [{ on, attack?, from?, to? }…], hits = 1 }
```

- **`still: true`** (или `form.still`): босс не ходит и не падает (в том числе оглушённый), `move` его приёмов игнорируется, держится в точке `place` (центр по `x`, низ на `y` px над полом; без `place` — точка появления арены; `y > 0` — босс «висит на стене»). Летающий неподвижный висит на заданной высоте.
- **Защита от читов у неподвижного**: чтобы его нельзя было «пересидеть» вдали, куда не достают приёмы, счётчик покоя `relocate` идёт при любой дистанции, и через `relocate.sec` срабатывает `antiCheese.relocateChain`. Она обязательна (иначе валидатор: ошибка `still-relocate`) и должна накрывать героя там, где он стоит: снаряд/удар `from/at: "target"` или запуск зоны арены `fire` (иначе предупреждение `still-relocate-reach`: на далёкой высокой платформе герой остался бы в безопасности). Отгон (`shoveChain`) работает как у остальных.
- **Уязвимые точки** (`weak` у босса или в `form`): удар засчитывается, только если коробка удара героя задевает **открытую** точку; остальное тело — броня (звон `clink`, искры, подсказка «Броня: бей в светящуюся уязвимую точку»). Оглушённый босс броню теряет; урон без замаха (яд, ожог, инструменты, всполох) идёт, пока открыта любая точка. `hits` — сколько единиц урона наносит удар по точке.
  - `box` — от левого верхнего угла тела; `mirror: true` — `x` отсчитывается от переднего края (зеркалится по взгляду);
  - `open` — окна «или»; пусто — открыта всегда. `on`: `always`, `idle`, `tell`, `active`, `recover`, `punish` (окно наказания), `stagger`; `attack` — только во время этой атаки; `from`/`to` — кадры от начала состояния (для `punish` — от начала окна). Окно короче `rules.weak.minOpenFrames` (24) — предупреждение, точка, открытая меньше нормы или недостижимая, — ошибка (`weak-short`, `weak-unreachable`, `weak-none`).
  - Рисуется общим кодом поверх любого тела: открытая точка светится и пульсирует, закрытая перечёркнута.
- Помощники: `weakStates(boss)` (`exec.ts`) — точки с прямоугольниками и флагом `open`, `weakOpen`, `weakRect`.

```json
{ "id": "mur", "still": true, "size": { "w": 80, "h": 100 }, "place": { "x": 0.55, "y": 0 },
  "weak": [{ "id": "core", "box": { "x": 20, "y": 40, "w": 40, "h": 40 }, "open": [{ "on": "punish" }, { "on": "recover", "from": 0, "to": 60 }] }],
  "antiCheese": { "shoveChain": "c_shove", "relocateChain": "c_hail" } }
```

## Существа-приспешники

```
BossDef.creatures: [{ id, name?, size, hp, speed = 60, fly?, life?, fade = 30, max = 3, contact?, beads = 0, color, draw?,
                      vanishOn = ["bossDeath"] (| "phase" | "stagger"), attacks: [Attack…], chains: [{ id, steps: [attackId…], weight }], rest: [min, max] }]
Attack.summon: [{ at, creature, ox, oy, count }]      Spawner.timeline: [{ …, creature }]
```

Существо — обычный враг мира (`type: "dmin"` в `sc.enemies`, данные в `e.m`): герой бьёт его обычным оружием, бот копирует его вместе с миром. Появляется по `attack.summon` (кадр от конца замаха; `ox` вперёд, `oy` от центра босса) или по записи точки появления арены. Ходит к герою или летает на `fly.hover`; **исчезающее**: через `life` кадров (за `fade` кадров до того бледнеет и безвредно), при `vanishOn` (смерть босса, смена фазы, оглушение) и когда его убьют. **Свои мини-связки**: `attacks` — тот же язык атак (замах, удары, снаряды, восстановление), `chains` — последовательности id этих приёмов, выбор по весу (`sc.rngFor('minion')`), пауза `rest`. **Общий лимит**: `max` одновременно на вид и `rules.minions.maxTotal` (8) на весь бой, лишние призывы пропадают. Валидатор: замах приёма существа не короче нормы `minTellFrames`, `fade < life`, существо должно где-то призываться. Свой рисунок — `'creature:<id>'` в `view/draw/boss/<id>.ts`.

```json
"creatures": [{ "id": "wisp", "size": { "w": 20, "h": 20 }, "hp": 2, "speed": 70, "fly": { "hover": 50, "speed": 100 }, "life": 360, "fade": 40, "max": 2,
  "contact": { "dmg": 1, "kind": "dodge" }, "vanishOn": ["bossDeath", "stagger"],
  "attacks": [{ "id": "spit", "tell": { "frames": 26, "cue": { "color": "yellow", "sfx": "spit", "pose": "puff" } },
    "spawn": [{ "at": 0, "proj": { "kind": "spore", "w": 10, "h": 10, "life": 120 }, "kind": "parry", "vx": 260, "vy": -120, "aim": true }],
    "recovery": { "frames": 30, "punishWindow": { "from": 4, "to": 24 } } }],
  "chains": [{ "id": "m_spit", "steps": ["spit"] }], "rest": [60, 90] }]
```

## Сущности арены по расписанию

Раздел `arena: { "level": "vladik", "ents": [...] }`. Координаты: **x — px от левой внутренней стены, y — px от пола вверх до нижней грани области**, `w`/`h` — размеры (внутри арены `vladik`: ширина 1344, высота от пола 448). Платформы и барьеры кратны тайлу 32 px.

```
Ent (общее): { id, kind, bind?: { start? | phase?: [n…] | chain?, step? }, loop? }   — без bind запускается вручную (attack.fire, дирижёр)
platform:  { area, solid = false, shown = false, timeline: [{ at, op: "show"|"hide", warn = 0 } | { at, op: "move", to: { x, y }, frames }] }
barrier:   { area, shown = false, timeline: […как у platform…] }              — всегда твёрдый
beam:      { area, hit: parry|dodge|unblockable, dmg = 1, timeline: [{ at, tell, active, aim = false, area? }] }
spawner:   { pos: { x, y }, timeline: [{ at, tell = 0, proj?: {…}, creature?, kind = dodge, vx, vy, aim, count, spread, dmg? }] }
```

- **Запуск**: `bind.start` — с концом вступления босса; `bind.phase: [2]` — с началом фазы (запускается заново, сущности других фаз гаснут); `bind.chain` + `step` — с началом шага связки; `attack.fire: [{ at, ent }]` — в кадр атаки; `conductor.schedule[].arena` — по такту дирижёра. Время `timeline` — кадры от запуска. У привязанных к связке и к `attack.fire` часы — кадры исполнителя босса (замедление босса замедляет и их), оглушение босса гасит всё, что запустила его связка; у остальных — кадры мира. `loop` — период повтора расписания.
- **Платформы и барьеры — динамические тайлы мира** (`sc.dyn`, поверх карты; сама карта `grid` не меняется, бот копирует `dyn` вместе с миром): проходимая платформа — `PLAT` (снизу проходима, сверху держит), `solid: true` и барьер — `SOLID`. Герой, босс и снаряды сталкиваются с ними теми же `tileAt`/`isSolid`, что и с картой. `show` с `warn` — сначала мигающий пунктир, потом платформа; `hide` с `warn` — мигает, потом исчезает; твёрдая платформа не вырастает внутри героя, босса или существа (ждёт, пока освободят место). `move` — ход по клеткам: за `frames` кадров платформа шагает по клетке к цели; тела на её верхней грани едут вместе с ней, твёрдая платформа не давит стоящих на пути.
- **Лучи и зоны урона**: замах `tell` кадров (контур и заливка цвета типа удара, мигание ускоряется), затем `active` кадров урона; каждый герой получает по одному удару от одной записи расписания (как у `active` босса), `hit` определяет отбив/рывок (`dodge` — рывок сквозь, `unblockable` — не гасится). `aim: true` — зона следит за x героя во время замаха и фиксируется к концу.
- **Точки появления**: снаряд (`proj`, как у `Spawn`, скорость в мировых осях) или существо (`creature`) через `tell` кадров предупреждения (пульсирующий круг цвета типа удара).
- Рисует универсальный `view/draw/arena.ts`: арта не требуется; контуры предупреждений — цвета телеграфа боссов (жёлтый/красный/фиолетовый), платформы перед исчезновением и появлением мигают белым пунктиром.
- Нормы (`rules.arena`): предупреждение платформы не короче `minWarnFrames` (30) при исчезновении любой и при появлении твёрдой, ход клетки не быстрее `minStepFrames` (10) кадров, не больше `maxEnts` (24) сущностей, под зонами урона в любой момент остаётся пол или платформа не уже `minSafeWidth` (64) px.

```json
"arena": { "level": "vladik", "ents": [
  { "id": "plat", "kind": "platform", "area": { "x": 320, "y": 96, "w": 128, "h": 32 }, "bind": { "start": true }, "loop": 600,
    "timeline": [{ "at": 0, "op": "show", "warn": 30 }, { "at": 240, "op": "hide", "warn": 40 }, { "at": 420, "op": "show", "warn": 30 }] },
  { "id": "beam", "kind": "beam", "hit": "dodge", "area": { "x": 0, "y": 0, "w": 200, "h": 60 }, "bind": { "chain": "c_beam", "step": 0 },
    "timeline": [{ "at": 0, "tell": 40, "active": 20 }] },
  { "id": "rain", "kind": "spawner", "pos": { "x": 700, "y": 250 }, "bind": { "phase": [2] }, "loop": 300,
    "timeline": [{ "at": 0, "tell": 30, "proj": { "kind": "rock", "w": 16, "h": 16, "life": 120 }, "kind": "dodge", "vy": 200 }] }
] }
```

## Несколько боссов: дирижёр

В бою до трёх боссов: ведущий (индекс 0, его JSON содержит раздел `conductor`) и один–два участника (`sc.bosses[1..2]`, их определения — отдельные файлы `data/bosses/<id>.json`, обычно `hidden: true`).

```
conductor: { members: [{ boss, place?: { x?, y? }, policy = "conductor" | "own" }], lead = "conductor" | "own", pool = false, win = "all" | "any",
             beat, cycle, schedule: [{ beat, boss: 0…2 | "all", chain, arena? }], relay: [{ from, chain, to, next, after = 0 }] }
```

- **Здоровье**: у каждого свой (`hp` из его файла) или общий пул (`pool: true`: у всех одно значение, берётся у ведущего; удар по любому снимает у всех; фазы — по общей доле). **Победа**: `win: "all"` — убиты все, `"any"` — убит любой (остальные падают вместе с ним), при общем пуле — обнулился пул. Полоса босса в интерфейсе — общий пул или сумма здоровья.
- **Расписание по такту**: часы дирижёра — кадры мира, идут, когда все вышли из вступления. Каждые `beat` кадров считается такт; цикл — `cycle` тактов. В такт `beat` цикла босс `boss` (индекс, `"all"` — все) начинает связку `chain` (связка из **его** файла), если он стоит в покое и не оглушён; занятый босс пропускает приказ (`sc.cond.skips`). `arena` — заодно запустить сущность арены. Участник с `policy: "conductor"` сам связки не выбирает (защитные «отгон» и «перемещение» работают всегда — защита от читов у каждого босса своя).
- **Фазы дирижёра**: приказ уважает `requires.phase` связки (в чужой фазе он молчит), поэтому «голоса» расписания включаются по фазам: связка с `requires: { phase: [2, 3] }` в фазе 1 не начинается, а валидатор разворачивает расписание отдельно для каждой фазы (сообщения с префиксом «фаза N:»). Расписание без `requires.phase` проверяется как раньше, одним списком. Образец — `data/bosses/mantises*.json`.
- **Эстафета**: когда босс `from` **закончил** связку `chain` (не прервал оглушением), босс `to` через `after` кадров начинает связку `next`; если он занят, ждёт до 180 кадров.
- **Безопасные окна по всем**: валидатор разворачивает расписание на два цикла, собирает удары всех боссов и проверяет: поток урона за 3 с (общий предел `maxDamage3s`), неотбиваемые удары разных боссов не ближе `minGapAfterUnblockable`, самое долгое окно без атак любого босса — не короче `max(minChainPunishFrames, rules.conductor.minSafeGapFrames)`; окна наказания каждого босса, перекрытые чужими атаками, — предупреждение `cond-punish-covered`. No-hit бот проходит бой целиком (`scanFight`).
- Состояние — `sc.cond` (`{ clk, relay, skips, over }`); тренировка «с фазы N» выставляет фазу всем.

```json
"conductor": { "members": [{ "boss": "twin_b", "place": { "x": 0.2 } }, { "boss": "twin_c", "place": { "x": 0.8 } }],
  "pool": false, "win": "all", "beat": 60, "cycle": 6,
  "schedule": [{ "beat": 0, "boss": 0, "chain": "c_a" }, { "beat": 3, "boss": 1, "chain": "c_a" }, { "beat": 4, "boss": 2, "chain": "c_a" }],
  "relay": [{ "from": 1, "chain": "c_a", "to": 0, "next": "c_b", "after": 10 }] }
```

## Особая логика: `kinds/<id>.ts`

```ts
import type { BossKind } from '../kinds';
export default {
  frame(k) { /* каждый кадр исполнителя */ },
  onPhase(k, phase) {}, onAttack(k, attackId) {}, onDeath(k) {},
  fx: { boom(k, args) { /* attack.fx: [{ at, name: "boom", args: { … } }] */ } },
  allow(k, chainId) { return true; },   // дополнительно запретить связку
} satisfies BossKind;
```

`k` (`KindApi`): `{ sc, b, d, def, i, rng }` — мир, босс, его `DState`, определение, индекс в `sc.bosses` и поток ГСЧ боссов (`sc.rBoss`; Math.random в ядре запрещён линтером). Файл подключается раньше исполнителя, поэтому **модули исполнителя, мира и урона из `kinds/*.ts` импортируются только типами** (`import type`; правило ESLint `no-restricted-imports` это проверяет); значения из `balance`, `constants`, `rng`, `schema`, `shared` брать можно. Тесты регистрируют хуки вручную: `registerKind(id, kind)` / `unregisterKind(id)`.

## Новые проверки валидатора (волна 0)

| Код | Уровень | Что ловит |
|---|---|---|
| `form-empty`, `form-blocked` | ошибка / предупр. | набор приёмов тела не оставляет ни одной связки политики / отрезает часть связок |
| `fly-ceiling`, `fly-low`, `body-size` | ошибка / предупр. | летающее тело упирается в потолок, висит ниже 16 px, тело больше арены |
| `still-relocate`, `still-relocate-reach`, `still-move`, `still-walk` | ошибка / предупр. | неподвижный без перемещающей связки, не достающей героя, и мелочи |
| `weak-short`, `weak-unreachable`, `weak-none`, `weak-window`, `weak-box` | ошибка / предупр. | уязвимая точка не успевает открыться, привязана к недостижимой атаке, вне тела |
| `creature-tell`, `creature-recovery`, `creature-fade`, `creature-unused`, `creature-harmless`, `creature-max`, `summon-over` | ошибка / предупр. | честность приёмов существ, исчезновение, потолки |
| `plat-hide-warn`, `plat-show-warn`, `plat-fast`, `beam-tell`, `beam-aim`, `spawn-tell`, `ent-bounds`, `ent-count`, `ent-unused`, `barrier-forever` | ошибка / предупр. | предупреждения и скорости сущностей арены, выход за арену |
| `beam-no-safe` | ошибка | зоны урона одной группы (фаза, шаг связки, атака) в какой-то кадр закрывают весь пол и все платформы |
| `cond-member`, `cond-chain`, `cond-flux`, `cond-unblock`, `cond-no-window`, `cond-overlap`, `cond-punish-covered` | ошибка / предупр. | дирижёр: нет участника или связки, общий поток урона, неотбиваемые подряд, нет окна без атак, рассинхрон приказов |
| `scene-unskippable`, `duel-wiring` | предупр. | длинная непропускаемая сцена; `duel: true` без подключённого запуска раунда |

Ошибки схемы и ссылок (неизвестная атака/связка/существо/сущность арены, сцена длиннее нормы, платформа не по тайлам, событие вне сцены) отвергаются при **загрузке** файла (`parseBossDef`) с понятным текстом, остальное — в отчёте `npm run boss:check`.

## No-hit бот и «злые» боты (волна 0)

- `scanChains` теперь ходит по копии мира с платформами, лучами и существами арены (динамические тайлы копируются с миром); связка считается законченной, когда отработали и запущенные ею сущности арены. Неподвижные боссы проверяются с одной позиции, остальные — с трёх.
- `scanTransitions` — каждый переход в фазу ≥ 2: рёв, **полная** сцена (клавишей бот её не пропускает), переходный приём и сущности арены новой фазы без единого удара.
- `scanFight` — бой под дирижёром (или любой бой) 2 цикла расписания: бот только уходит от всех боссов. `runFlawless` умеет убивать нескольких боссов; бьёт открытые уязвимые точки, статистика связок идёт по `босс:связка`.
- `npm run boss:nohit -- --boss id` печатает проходимость связок, переходов и боя под дирижёром.
- `boss:cheese`: боты играют против ближайшего живого босса; добавлены «отсидка у дальней стены» (`far-camp`) и «насест на самой высокой платформе» (`perch`); копия «без защиты» создаётся и для участников дирижёра (`bossRaw` в реестре хранит исходный JSON).

## Как добавить босса

Коротко: положить `data/bosses/<id>.json` (и при желании `src/core/boss/kinds/<id>.ts`, `src/view/draw/boss/<id>.ts`) — больше ничего подключать не нужно. Полная инструкция с чек-листом валидатора и ботов — `docs/BOSS_HOWTO.md`.
