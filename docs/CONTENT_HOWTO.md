# Как добавить вещь в игру, не трогая ядро

Каждая вещь игры описывается **одним файлом логики** в `src/content/<вид>/` и, если её видно или слышно, **одним файлом вида** в `src/view/content/<вид>/`. Файлы находятся сами: в Vite и Vitest через `import.meta.glob`, в Node-инструментах (бот, фаззер, `boss:*`) через чтение папки (`src/content/node.ts`, подключается ключом `--import ./tools/ldtk-register.mjs`). Ядро не знает имён конкретных вещей. Оно вызывает описание из реестра (`src/core/plugin/regs.ts`).

Боссы устроены так же, только отдельно: `data/bosses/<id>.json` и при необходимости `src/core/boss/kinds/<id>.ts` и `src/view/draw/boss/<id>.ts`. Подробно — `docs/BOSS_HOWTO.md`.

| Вид | Логика | Вид и звук | Набор для описания |
|---|---|---|---|
| Оружие | `src/content/weapons/<id>.ts` | `src/view/content/weapons/<id>.ts` | `src/core/weapon-kit.ts` |
| Инструмент (навык нити) | `src/content/tools/<id>.ts` | `src/view/content/tools/<id>.ts` | `src/core/tool-kit.ts` |
| Оберег | `src/content/charms/<id>.ts` | — (цвет значка в описании) | `src/core/charm-kit.ts` |
| Приём набора | `src/content/abilities/<id>.ts` | `src/view/content/abilities/<id>.ts` | `src/core/ability-kit.ts` |
| Враг | `src/content/enemies/<id>.ts` | `src/view/content/enemies/<id>.ts` | `src/core/enemy-kit.ts` |
| Снаряд | `src/content/projectiles/<id>.ts` | `src/view/content/projectiles/<id>.ts` | `src/core/proj-kit.ts` |
| Арена босса | `src/content/arenas/<id>.ts` | `src/view/content/arenas/<id>.ts` | `src/core/arena-kit.ts` |
| Звук | — | `src/view/content/sounds/<группа>.ts` | `defineSounds` в `src/view/content/regs.ts` |

Самый быстрый путь: скопировать похожую вещь, сменить `id`, `order` и `netId` (если есть) и поменять поведение.

## Правила, которые нельзя нарушать

1. **`order` — место в списке.** От порядка зависят выбор в фаззере, списки в интерфейсе, порядок срабатывания хуков, а значит детерминизм и золотые записи. У существующих вещей `order` не меняют. Новая вещь получает `order` больше всех прежних. Тест `tests/unit/content.test.ts` проверяет, что прежние вещи стоят на своих местах. Новую вещь можно добавить, не меняя тест.
2. **`netId` — код на проводе** (снаряды, сущности инструментов). Он уникален и только добавляется: 0–7 заняты снарядами, 8–12 — сущностями инструментов. Следующий свободный — 13. Реестр сам сообщит о занятом коде.
3. **Детерминизм.** В логике нельзя использовать `Math.random`, `Date.now` и таймеры. Случайность берётся из потоков мира (`sc.rEnemy()` и др.), время — из `dt` и счётчиков кадров. В файлах вида (`src/view/content`) можно всё: они на ход игры не влияют.
4. **Импорт в файлах логики.** Модули ядра импортировать можно, но вызывать их только внутри функций. На верхнем уровне файла — только `export default defineX({...})`. Иначе возникают циклы загрузки модулей.
5. **Логика не знает про отрисовку.** `src/content` не импортирует `src/view`. Вид видит ядро только через типы и данные мира.
6. **Сетевая игра.** Считает мир хост, гость получает снимок. Всё, что меняет мир, делайте под `sc.auth()` или в функциях, которые ядро вызывает только у хоста (это написано у каждого хука в наборе).

## Оружие (≈10 минут)

`src/content/weapons/<id>.ts`:

```ts
import { defineWeapon, fr } from '../../core/weapon-kit';

export default defineWeapon({
  id: 'whip', order: 5, name: 'Нить-хлыст', col: 0xffc8a0, desc: '…', unlock: 'shop:60',
  reach: 1.6, thick: 0.6, atkT: 0.16, cd: 0.4, combo: 2, comboWin: 0.6, dmg: 1.1,
  pm: 1, kb: 1, recoil: 1, hs: 0.04,
  geo: { f: [90, 20, -6], u: [40, 70, 60], d: [40, 60] },
  sw: { /* особые удары по ключу: f, a1, a2, c (заряд) … — см. lance.ts, sickle.ts */ },
});
```

`unlock`: `'shop:<цена>'` — продаётся в лавке, `'boss:<id>'` — награда за босса. Вид — `src/view/content/weapons/<id>.ts` (`defineWeaponView`): клинок за спиной `back`, поза заряда `pull`, рисунок удара `swing` и заряда `charge`, высота гула заряда `chargePitch`. Образцы: `lance.ts` (простые уколы), `mace.ts` (особый эффект заряда через `onCharge` / `chargeShake`).

## Инструмент

`src/content/tools/<id>.ts` — `defineTool({ id, order, name, desc, cost, cd, unlock, use? | spawn?, entities?, msgs? })`.

- **`spawn(sc, m)`** создаёт сущность в `sc.tl` у хоста. Гость присылает сообщение `tool`, и `spawn` вызывается уже у хоста.
- **`entities`** — виды сущностей: `{ id, netId, size, step, netCh? }`. `step` — шаг у хоста, `netCh` — дополнительные числа в снимке.
- **`use`** — мгновенный эффект без сущности (как у `dive`).

Вид — `defineToolView({ id, icon, ents: { <сущность>: рисунок }, fx?, world? })`. Образцы: `trap.ts` (сущность на земле), `throwneedle.ts` (летящая сущность), `hook.ts` (общий слой `world`).

## Оберег

`src/content/charms/<id>.ts` — `defineCharm({ id, order, name, desc, unlock, slots, col, ...хуки })`. Хуки:

| Хук | Когда вызывается |
|---|---|
| `silkGain` | начислена нить |
| `hitEnemy` | удар героя ранил врага |
| `hitBoss` | удар героя ранил босса |
| `hurt` | героя ранили |
| `exec` | герой казнил оглушённого босса |
| `stepPre` | в начале шага героя |
| `stepPost` | после шага героя |

Кроме хуков, есть данные: `maxHp` (прибавка к здоровью) и `beadPull` (бусины тянутся издалека). Хуки срабатывают в порядке `order` оберегов, а не в порядке, в котором их надел игрок. Образцы: `thorns.ts` (`hurt`), `hunter.ts` (`hitEnemy`), `heart.ts` (`maxHp`).

## Приём набора

`src/content/abilities/<id>.ts` — `defineAbility({...})`. Это самый сложный вид: приём перехватывает шаг героя. Опишите:

- **`armed`** — когда приём может начаться;
- **`drive`** — вести шаг, пока приём активен;
- **`cancel` и `clear`** — срыв и сброс состояния;
- **`code` и `codes`** — коды состояния для сети и отрисовки. Они общие для всех приёмов и только добавляются: заняты 1–6.

Порядок `order` решает, какой приём перехватит кадр. Образцы: `flash.ts` (короткий рывок), `crystal.ts` (заряд и полёт), `counter.ts` (окно реакции в `pre`). Вид — `defineAbilityView({ id, icon, fx: { <код>: рисунок }, trails?, pose? })`. Награда за босса — `unlock: 'boss:<id>'`: событие `bossReward` открывает приём само.

## Враг

`src/content/enemies/<id>.ts` — `defineEnemy({ id, order, spawn, step, ...реакции })`.

- **`spawn(sc, d, base, { fx, fy })`** возвращает массив врагов (стая — несколько). Порядок вызовов `sc.rEnemy()` — часть детерминизма.
- **Реакции на удары:** `blocked` (броня), `parryCrack`, `meleeKb` / `toolKb`, `onHit`.
- **Флаги:** `flies`, `trapImmune`, `heavy`, `dotImmune`.
- **«Враг 2»** (`e2: true`) — броня и состояния. Список `states` уходит гостю индексом.

Враг ставится в уровень точкой Enemy с полем `type` = `levelType ?? id`. Новый вид сам попадает в список типов LDtk при `npm run levels:export`. Образцы: `gnat.ts` (летает), `shell.ts` (броня, `e2`), `bat.ts` (стая из одной точки, `levelType: 'bats'`). Вид — `defineEnemyView({ id, draw })`.

## Снаряд

`src/content/projectiles/<id>.ts` — `defineProj({ id, order, netId, size, step, ...флаги })`:

| Поле | Что делает |
|---|---|
| `step(sc, pr, dt)` | движение и столкновение со стенами у хоста; `guest(pr, dt)` — гравитация и вращение у гостя |
| `persist` | не исчезает, попав в героя |
| `heavy` | урон по умолчанию 2 |
| `slash` | срезается обычным ударом (`true` — золотые искры и звон; объект — своя реакция `onCut` и `guestCut`) |
| `cutAll` | срезается только ударом «рубит всё» |
| `dieOnStagger` | гаснет, когда босс оглушён |
| `hero` | снаряд героя: не ранит героев, не гаснет при смене фазы |
| `data: true` | можно задавать в `data/bosses/*.json` (`proj.kind`) |

Вид — `defineProjView({ id, draw, round? })`. Во время задержки (`pr.delay > 0`) предупреждение рисует сам вид (общий треугольник на полу — `_floor.ts`).

## Звук

Добавьте строку в подходящую группу `src/view/content/sounds/*.ts` или создайте свою группу:

```ts
export default defineSounds({
  pyre: (s) => { s.hiss(0.4, 0.2, 700, 0.8); s.tone('sawtooth', 160, 60, 0.4, 0.12); },
});
```

У `s` есть методы `tone(тип, f0, f1, длительность, громкость)`, `hiss(длительность, громкость, частота, q)` и `later([мс…], fn)`, а также `ctx` и `master` для своих цепочек (образец — `violin` в `base.ts`). Второй аргумент `R` — `Math.random` (только для вида). Имя звука называют ядро (`sc.sfx('имя')`) и данные боссов (поле `sfx`). Если имя не заведено, игра один раз пишет предупреждение в консоль. Полный список незаведённых имён печатает `npm run content:check`.

## Арена босса

1. Уровень арены в `levels/tropa.ldtk` с точкой босса. Сейчас файл собирает генератор `tools/ldtk-export.ts` из `tests/oracle/levels-code.ts`, а тест `levels.test.ts` сверяет файл с генератором. Поэтому новый уровень добавляйте в генератор (`npm run levels:export`).
2. `src/content/arenas/<id>.ts`:

   ```ts
   export default defineArena({ id: 'roof', order: 3, name: 'Крыша', ldtk: 'ArenaRoof', spot: (L) => L.boss });
   ```

   `spot` — точка босса в тайлах: от неё считаются пол арены и место появления.
3. Убранство (по желанию) — `src/view/content/arenas/<id>.ts`: `decor({ scene, w, keep, font, display })` рисует надписи и предметы (каждый объект передайте в `keep`). `bursts: { <событие>: { key, cfg, depth } }` — частицы по событию: в логике `sc.fxAt('<событие>', n, x, y)`. Хост сам перешлёт событие гостю.
4. В данных босса: `"arena": "<id>"` или `{ "level": "<id>", "ents": [...] }`.

## Проверка

```bash
npm run content:check          # что найдено по видам; ошибки полноты (нет отрисовки, неизвестный снаряд или арена); незаведённые звуки
npm run content:check -- --json # то же для стенда
npm run test:fast              # юнит-тесты, в том числе content.test.ts и золотые записи
npm run boss:check             # если вещь используют боссы на данных
```

Золотые записи (`tests/golden/**`) не должны меняться от новой вещи: в них снаряжение задано явно. Фаззер (`npm run fuzz`) берёт снаряжение из реестров, поэтому новая вещь сразу попадает в случайные прогоны. Его прогоны с тем же зерном после добавления вещи идут по-другому, и это нормально.

## Что пока не подключается файлом

- **Главы кампании** — таблица `CHAPTERS` в `src/core/balance.ts`. Босс главы меняется одной строкой. Новая глава требует уровней, коридора и сюжета, поэтому это не «одна вещь».
- **Режимы и меню** (кампания, Босс-тест, Босс-раш, гонки, дуэль) связаны с сессией, сетью и журналом. Добавить режим — работа в ядре.
- **Наблюдение нейросети** (`src/agent/obs.ts`) заморожено: списки видов связаны с весами модели. Новые виды попадают в слот «прочее».
- **Формат журналов и `.ttrec`**: строки режимов и id не меняются.
