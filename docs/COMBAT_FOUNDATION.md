База изменений: `40d7bdd` (`main`, перенос содержимого в подключаемые модули).
Новые боссы в этом изменении не добавляются. Цель — исправить общие правила,
от которых будут зависеть все последующие бои.

## Контракты для нового содержимого

`BossHit` принимает `amount`, `shape` (rect/circle), `source` и способ проверки
уязвимой точки. `geometry` требует пересечения формы с открытой точкой;
`open` предназначен для уже наложенного эффекта; `bypass` — для казни.
Оглушение временно открывает тело, как и раньше. HP меняется только после
проверки допустимости попадания. `rawData` возвращает outcome и фактический damage.

Новые поля атак необязательны: старые описания продолжают загружаться.

```json
{
  "counter": { "windowFrames": 6, "reach": 70, "grounded": true },
  "tell": {
    "frames": 30,
    "commitFrames": 8,
    "cue": { "color": "yellow", "sfx": "thrust", "pose": "ready" }
  }
}
```

`counter: false` запрещает контрудар независимо от цвета; без поля действует
прежнее правило цвета. `spawn.aimTarget: locked` использует сохранённую точку,
`live` — позицию героя при выстреле. `conductor.commands: policy` включает полные
условия политики; по умолчанию scripted сохраняет постановочное расписание,
но уважает фазу и доступные текущей форме атаки.

`ProjDef.parryClear` и `burstClear` управляют удалением защитными действиями.
Без настройки отбив удаляет только parry/старые нетипизированные снаряды;
всполох удаляет вражеские активные снаряды. `cancelOnInterrupt` удаляет только
снаряды текущего экземпляра атаки с соответствующими `o` и `attackId`.
`swept: false` отключает проверку траектории для телепортирующихся объектов.

Клавиатура игрока 1: T — отбив, Y — лечение, H — всполох. Назначения меняются
в настройках; миграция выбирает свободную клавишу, если T/Y/H уже заняты.
Игрок 2: Num6/7/8. Геймпад: нажатие правого стика — отбив, левого — лечение,
оба — всполох. Сенсорная кнопка нити пока сохраняет объединённое поведение Q.

Журнал сохраняет прежние 17 бит каждого игрока; новые шесть бит на игрока
добавляются в позиции 34–45. Старые записи читаются, новые требуют обновлённого
ядра. Версия контейнера журнала остаётся v1; сетевые id содержимого не меняются.

## Проверки и ожидания записей

- `npm run test:combat` — короткие регрессии изменённой основы.
- `npm run test:fast` — расширенный локальный набор.
- `npm test` — полный набор, включая ботов, no-hit, переходы фаз и повторы.
- `npm run content:check`, `npm run boss:check` — реестры и данные.
- `npm run build`, затем `npx playwright test tests/e2e/combat.spec.ts tests/e2e/smoke.spec.ts` — браузер.

GitHub CI запускается только вручную. Push и PR не повторяют локальные проверки.
Отдельный Deploy по-прежнему публикует main; это изменение его не затрагивает.

Записи v2 пересняты из-за исправлений боевой логики; каждый новый журнал
проверен воспроизведением самим рекордером. Оригиналы v1.8 не изменены.
Три `tests/golden/current` фиксируют намеренное отличие сброса при возрождении
на прежнем вводе; SHA-256 привязывает ожидание к неизменённой исходной записи.
Диагностика: временное отключение нового сброса воспроизводит все три старых
ожидания, отключение swept collision — не воспроизводит.

## Очистка репозитория

Удалены одноразовый `V2_PROMPT.md` и устаревшая служебная памятка `STAND_REPLY.md`.
Инструкция локальной разработки обновлена для main и ручного CI; зависимости
legacy теперь устанавливаются только по необходимости. Игнорируются coverage,
кэш сборки, Python bytecode и локальные виртуальные окружения.

Анализ ссылок на исходники не обнаружил лишних модулей игры: файлы содержимого,
видов боссов и отрисовки без прямых импортов загружаются автообнаружением.
`legacy/`, оракулы уровней, исторические измерения и записи сохранены: их читают
тесты и инструменты. Удаление архива потребует отдельного отказа от этих проверок.

## Что ещё нужно перед сложными боссами

Это исправление основы, а не доказательство отсутствия всех дефектов игры.
Следующий этап требует отдельных решений и проверки ощущений в игре:

1. Общая шкала кадров действий героя: сейчас есть проверка занятости и отмена,
   но времена melee, парирования и движения по-прежнему задают разные модули;
   нет полного декларативного FSM игрока с таблицей прерываний.
2. Изменяющиеся хитбоксы melee и swept-контакты героя с движущимся боссом;
   для снаряда, погашенного плагином о стену, общий шаг пока не вычисляет
   отдельное время контакта со стеной.
3. Отдельные сенсорные кнопки и удобство новых команд на разных контроллерах.
4. Источник стойкости для всех призванных существ и правил группового боя.
   Старые вызовы без источника сохраняют прежнюю проверку ближайших боссов.
5. Расширенный редактор телеграфов для расписаний арены, звуковая оценка на слух,
   обучение языку атак и проверка читаемости в настоящем бою.
6. Боссы по сети всё ещё отключены существующим `netBossBlock`: синхронизация
   их FSM/арен требует отдельной реализации. Этот патч её не добавляет.
7. Матрица no-hit по каждому оружию, приёмам, двум игрокам и переходам фаз;
   добавленная поддержка профилей позволяет строить её без изменения ядра.

Полноценного плейтеста сложности и удовольствия автоматические проверки не заменяют.
