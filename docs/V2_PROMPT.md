# Промт перехода на v2.0 (адаптирован под v1.8)

Ты ведёшь большой переход игры «Тропа Ткачей» на целевой стек (версия 2.0). Репозиторий Rus25-dev/tropa-tkachei
склонирован, ты в его корне. Сайт: https://rus25-dev.github.io/tropa-tkachei/ (GitHub Pages из main).
Отвечай и комментируй по-русски. Моя машина: Windows, NVIDIA RTX 5080 (16 ГБ), 24 потока CPU.

════════ ЦЕЛЬ ════════
Один раз перевести игру на целевую архитектуру, без промежуточных рефакторингов, сохранив поведение **v1.8**
(механики, баланс, сохранения игроков, «Гонки Ткачей» этапа Б1: организатор, игрок, обсервер, надёжный канал,
журнал ввода), и уже на ней делать остальные гонки и дальнейший мир.
Целевой стек:
- Phaser 4.x (WebGL) — только отрисовка, ввод, звук-обёртка, камеры, фильтры. Сначала `npm view phaser versions`:
  берём последнюю стабильную 4.x (если 4.2 ещё нет — ту, что есть), версию фиксируем точно.
- TypeScript (strict) + Vite (+ vite-plugin-singlefile: на выходе один index.html для Pages; отдельная rating.html позже).
- Архитектура: core/ (правила, физика, герои, враги, боссы, снаряды, урон, фазы, стойкость, кампания, ГСЧ —
  чистый TS без Phaser/DOM, фиксированный шаг 1/60, ВСЕ таймеры в кадрах логики, без Date.now/Math.random/delayedCall),
  view/ (Phaser 4 рисует состояние ядра; звук и частицы по событиям из step()), net/ (PeerJS/WebRTC), ui/ (HTML/CSS + Preact).
- Боссы и враги — данными (состояния, атаки, телеграфы, окна для удара, параметры баланса в data/*.json)
  + общий автомат состояний в ядре.
- Уровни — редактор LDtk (levels/*.ldtk) + свой загрузчик в формат ядра.
- Хранение: настройки — localStorage (ключи tt_* как сейчас), журналы ввода и гонки — IndexedDB (idb-keyval).
- Тесты: Vitest для ядра, Playwright Test для экранов/сети/снимков, «золотые записи» партий как эталон поведения.
- CI: GitHub Actions на каждый PR.

════════ ЭТАП 3. ОТРИСОВКА НА PHASER 4 ════════
- view/ рисует состояние ядра: уровни (TilemapGPULayer там, где уместно), герои с надписями Di/Ta, враги, боссы,
  снаряды, HUD, полосы боссов, шкала стойкости, тосты с очередью. Внешний вид не хуже v1.8 (сравни скриншоты бок о бок).
  Тот же view/ используется обсервером гонок (две половины экрана) — проектируй его переиспользуемым с самого начала.
- Рендер в родном разрешении: логическое поле 960×540 (ширина по пропорциям экрана, как сейчас),
  холст = CSS-размер × min(devicePixelRatio, 2), камеры через zoom; текст не смещается.
- Статичное (декор, мебель, класс, фоны) — один раз в текстуры при входе в комнату; динамика — каждый кадр.
- Атмосфера: фильтры камеры — цветокоррекция по главам (мох холодно-зелёный, типография сепия, класс тёплый вечер,
  берлога неон), виньетка; bloom через Actions.AddEffectBloom только на «Высоком»; Gradient и Noise для фонов
  и тумана на видеокарте; освещение setLighting(true) у ламп, нити героя, глаз боссов (если укладывается в бюджет);
  световые пятна аддитивными спрайтами; частицы (пыль бега и приземления, искры иглы, фоновые листья);
  параллакс 3–5 слоёв с атмосферной перспективой.
- Анимация: сжатие/растяжение при прыжке и приземлении, плащ — цепочка 4–6 точек с простой физикой,
  вторичное движение (усы, рюкзак Миши, смычок Владика), ударная волна на казнях и сильных ударах;
  дуги и клинки разных видов оружия, заряд удара, нить инструментов.
- Настройка «Графика: Авто / Низкое / Среднее / Высокое»: Авто меряет FPS и снижает качество при просадке
  ниже 55 кадров дольше 2 с (без мигания). «Без вспышек» и «Контуры опасного» работают на всех уровнях.
- Режим ?perf=1: FPS, время логики/отрисовки, draw calls, память. docs/PERF.md с замерами: меню, глава I,
  каждый босс в 3-й фазе, кооп, обсервер гонки (две половины) — на ×1/×4/×6 замедлении CPU в Chrome DevTools и
  эмуляции iPhone 13 / Android 360×800. Требование: на ×6 и на эмуляции телефона не хуже v1.8 (замерь v1.8 так же).

════════ ЭТАП 5. СЕТЬ ════════
- PeerJS/WebRTC: хост считает мир на ядре, гость получает снимки состояния ядра и события; два канала —
  надёжный упорядоченный (события с номерами, догонка после обрыва) и ненадёжный (снимки/телеметрия);
  бинарная упаковка (msgpack или binarypack PeerJS); у гостя и обсервера буфер интерполяции 100–150 мс.
  Перенеси из v1.8 «надёжный канал» гонок (пульс, номера событий, догонка, ключ игрока) в общий слой net/ и используй
  и для коопа, и для гонок.
- Пульс, переподключение с экспоненциальной паузой, возврат в ту же комнату по личному ключу, 'bye' на pagehide.
- iceServers из data/net.json; поддержка своего TURN (предложи бесплатный вариант — Cloudflare Calls TURN
  или metered.ca — и что мне зарегистрировать; без секретов в репозитории). Запасной — текущий PeerJS.
- Тесты: транспорт-заглушка с задержкой 50–300 мс, потерями 1–10 % и обрывами + локальный PeerJS-сервер в CI;
  кооп в двух окнах: движение, урон, подбор предметов способностей гостем, общие бусины, смерть и подъём,
  обрыв нити у обоих, переход глав, уход гостя и хоста (никто не остаётся в коконе навсегда);
  гонка: организатор + 2 игрока + 2 обсервера, обрывы каждого участника, перезагрузка организатора,
  восстановление игрока по журналу.

════════ ЭТАП 7. ИИ-ИНСТРУМЕНТЫ НА МОЁМ ЖЕЛЕЗЕ ════════
- Бот: мозг из tools/botbrain.js на ядре; пул worker_threads (ядра − 2). `npm run bot -- table --fights 200`
  с доверительными интервалами; `npm run bot -- watch <запись>` — просмотр боя в браузере.
- Фаззер `npm run fuzz -- --hours 1`: все режимы, случайный и полуслучайный ввод, инварианты (нет NaN, герой не
  в стене, нет застреваний > 30 с без выхода, переходы глав, нет исключений, снимок хост→гость без расхождений,
  журнал ввода → воспроизведение даёт то же состояние); каждая находка — минимальная запись в tests/repro/
  и регрессионный тест.
- Запись партий игроками: настройка «Записывать мои бои» и ?rec=1 → файл .ttrec; `npm run replay -- file.ttrec`.
- Optuna (Python, ml/, venv, requirements.txt): `python ml/tune.py --boss korne --target "skill0.6:winrate=0.55..0.65,time=80..120"`
  меняет data/balance.json через бота и пишет отчёт с графиками в ml/reports/; в игру — только после моего одобрения.
- (Эксперимент, после всего остального) ml/rl/: Gymnasium поверх ядра, PyTorch со сборкой под CUDA 12.8+ (RTX 50),
  Stable-Baselines3 PPO, 20+ параллельных сред; проверить torch.cuda.is_available(); цели — агент против Корнематки,
  отчёт об эксплойтах, экспорт агента в ONNX как «призрак-соперник» (onnxruntime-web).
