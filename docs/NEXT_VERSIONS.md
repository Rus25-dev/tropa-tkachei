## Что уже сделано и что важно знать
- **Детерминизм.** `src/rng.js`: `mulberry32`, `this.rng()`, `this.rngFor('boss'|'loot'|'enemy')`; одно зерно + одинаковый ввод по шагам логики = одинаковый исход (`tools/determinism-test.js`). Логика идёт фиксированным шагом `STEP=1/60`.
- **Что мешает полному воспроизведению (сделать в v1.8):** смерть, возрождение и переходы глав привязаны к реальному времени через `this.time.delayedCall` (`respawnAll` ≈1350 мс, `win()` ≈3300 мс, переходы кампании) — перевести на счётчики кадров логики. Ввод при записи фиксировать **по шагам логики** (не по кадрам отрисовки): в `GameScene.update` на первом шаге кадра идут фронты нажатий (`pend`), на остальных — только удержание.
- **Сеть.** `src/net.js` (PeerJS, комнаты с кодом, ретранслятор при серых IP), хост считает мир, гость рисует по снимку (`packSnap/applySnap`) и событиям (`onEv`). Гонка 1×1: `src/speedrun.js` (сообщения `t:'race'`). Меню: `src/menu.js` (реестр `MENU`/`menuAdd`, `Dev`, `Ov`, `Nav`), экраны гонок «Скоро» — заглушка, подключить новым разделом.
- **Тесты.** `npm test` (быстрый), `npm run test:full`. В облачной песочнице НЕ дошли до конца и требуют локального прогона: `tools/menu-test.js` (layout, окно «Как играть» на 667×375), `tools/bugs3-test.js` (кнопки у левши — возможен флейк по таймерам), `tools/speedrun-test.js`, `tools/bugs2-test.js`.
- **Не проверялось на железе:** звук и вид эффектов, настоящий WebRTC между двумя устройствами, геймпады DualSense и Steam Deck, iPhone, поля ввода на iOS.

## Сквозные требования
1. **Надёжность (обязательно, самое важное для гонок):**
   - Канал: пульс (heartbeat), автоматический реконнект с экспоненциальной паузой, возврат игрока в ту же комнату по личному ключу, нумерация событий и догонка пропущенного после обрыва, ретранслятор при недоступности прямой связи.
   - Организатор: состояние гонки пишется в `localStorage` (try/catch); после перезагрузки страницы организатора восстанавливаются комната (тот же код), список игроков, ход гонки; игроки и обсерверы переподключаются сами.
   - Обсервер: при подключении запрашивает полный снимок гонки; не усыпляется при скрытом окне (не ставить на паузу по `visibilitychange/blur`), догоняет по последней телеметрии.
   - Игрок: при обрыве играет локально, время идёт, события копятся и отправляются после возврата. Отправка `bye` на `pagehide/beforeunload`.
   - **Восстановление забега игрока по журналу ввода** (лучше, чем только сохранение на скамье): писать сжатый журнал нажатий по шагам логики + зерно + настройки в `localStorage` каждые ~2 с; после падения/перезагрузки вкладки «Восстановить забег» воспроизводит журнал без отрисовки до того же шага (проверить скорость; при необходимости ускорять `step()` напрямую). Время простоя идёт в зачёт, в журнале это помечается (признак «восстановлен»). Нужен тест: оборвать вкладку посреди забега, восстановить, получить тот же исход.
   - Для одиночного спидрана — то же восстановление.
2. Всё, что создаётся в `this.*` лениво или по флагу, сбрасывай в `create()` — объект сцены переиспользуется.
3. Не использовать `Math.random`/`Date.now` в игровой логике. Версию `GAME_VERSION` и «Что нового» поднимай в `src/game.js` при каждом релизе. Не делать логику, зависящую от реального времени.
4. Проверка версии игры у всех участников гонки, запрет лёгкого режима и замедления.
5. Тесты на каждую версию, скриншоты экранов (5 размеров: 667×375, 844×390, 932×430, 1366×768, 1920×1080) — смотреть самому и убирать наложения. Новые модули — строкой в `parts` в `build.py` выше `update.js`.

## v1.8 — «Гонки Ткачей»: основа (этап Б1, часть 1)
Сценарий: организатор (не играет) создаёт ОДНУ гонку в ОДНОЙ дисциплине; двое игроков онлайн, каждый у себя; организатор стримит окно обсервера в Discord. Многодисциплинарных турниров не делаем, но каждая гонка сохраняет результат в едином формате.
- Комната `src/race-net.js`: организатор — центр PeerJS, принимает 2 игроков и N зрителей, сообщения `t:'rc'`, не ломая кооп и гонку из `speedrun.js`. Ссылки: `?race=org`, `?race=play&room=КОД`, `?race=watch&room=КОД`. Игрок вводит имя сам: сравнение без учёта регистра и пробелов, подсказки уже известных имён, у организатора в архиве «Объединить игроков».
- Игроки играют локально, шлют ~15 Гц телеметрию (герой, маски, нить, глава/этап/позиция, босс: HP/фаза/состояние, упрощённые снаряды) и события (сплит, смерть, покупка, казнь, отбив, смена фазы). Пинг, `bye`. Надёжность — см. «Сквозные требования».
- Панель организатора `src/race-org.js`: дисциплина и настройки, копирование ссылок игроков и обсервера, общий отсчёт 3‑2‑1, тех. пауза для обоих, переиграть, присудить победу, отменить действие, лог.
- Обсервер `src/race-watch.js` (1920×1080): две равные половины с картинкой игроков по телеметрии (переиспользуй отрисовку уровня, героев, боссов, снарядов; камера за игроком), центральное табло (таймер, имена, маски, HP боссов, фаза, разница времени), лента событий. Экран «До старта»: карточки игроков. После гонки: разбор.
- Статистика `src/race-stats.js`: время, урон, DPS, полученный урон, смерти, лечения, точность (попадания/взмахи), отбивы, идеальные увороты, оглушения, казни, самое длинное комбо, время по фазам, покупки в лавке.
- Формат результата: `{ id, date, version, discipline, settings, seed, players:[{name, place, time, finalTime, dnf, stats, splits, eloBefore, eloAfter}], winner, events[] }`; хранится у организатора в `localStorage`; кнопка «Скачать races.json».
- Минимальная дисциплина для проверки: «Тропа целиком» (подсплиты — в v1.10).
- Меню: заменить заглушку «Гонки Ткачей» (`src/menu.js`) рабочими пунктами: Создать гонку · Войти игроком по коду · Обсервер · Рейтинг и архив (рейтинг — v1.9).
- `tools/race-test.js` (Playwright, транспорт-заглушка как в `tools/speedrun-test.js`): организатор + 2 игрока + обсервер, форсированные победы реальными функциями урона, обрыв связи с догонкой, перезагрузка организатора, тех. пауза, обсервер рисует при скрытом окне, восстановление игрока по журналу.

## 2.1 (бывшая v1.9) — рейтинг, повторы, трансляция (этап Б1, часть 2)
- Рейтинг Эло: отдельный по каждой дисциплине («Тропа целиком», «Босс-раш», «Дуэль») и общий; старт 1000, K=40 для первых 10 гонок игрока, затем 24; шансы на победу по Эло на экране «До старта».
- `races.json` (полная история) → `data/races.json` в репозитории (организатор загружает файл через сайт GitHub).
- Публичная страница `rating.html` (собирается `build.py` рядом с `index.html`; ссылка из меню «Гонки Ткачей › Рейтинг»): читает `data/races.json`, пересчитывает Эло с нуля по истории (единственный источник правды), таблицы по дисциплинам и общая, профиль игрока (график Эло, рекорды, личные встречи, последние гонки), страница каждой гонки со сплитами. Без бэкенда; если файла нет — понятная заглушка.
- Картинка итогов для Discord: PNG 1200×675 (победитель, время, разница, ключевые сплиты, изменение Эло) — «Скачать PNG» и «Копировать в буфер».
- Анимация изменения Эло и перемещения мест после гонки.
- «Повтор момента»: обсервер хранит 10 с телеметрии каждого игрока; клавиша R1/R2 — повтор игрока 1/2 на его половине с плашкой «ПОВТОР», затем возврат в эфир.
- `?overlay=1` — прозрачный фон (табло и лента) для OBS. Режим `?race=watch&stream=1`: поле 16:9 по размеру окна без полей и прокрутки, курсор прячется через 2 с, интерактивные элементы скрыты; горячие клавиши: H — табло, 1/2 — половина игрока на весь экран на 10 с, 0 — обе половины, R1/R2 — повтор, Space — заморозить ленту.
- Звук обсервера: эффекты по событиям и музыка босса лидера, своя громкость (по умолчанию 60 %), «Без звука», разблокировка первым кликом. Обсервер НЕ ставится на паузу по `visibilitychange/blur`.
- Читаемость при сжатии Discord (720p): контрастные цвета, толстые обводки, ≥ 22 px на 1080p, ключевые цифры (таймер, разница) ≥ 48 px.
- README: раздел «Гонки 1×1 для стрима» (ссылки игрокам; стрим в Discord (Go Live → окно обсервера со звуком; окно не сворачивать — Chrome «усыпляет» скрытые окна; лучше второй монитор); OBS (источник «Браузер» 1920×1080 или `overlay=1`); как скачать `races.json` и загрузить в `data/` через сайт GitHub).
- Тест: `races.json` → `rating.html`, PNG итогов, повтор момента.
