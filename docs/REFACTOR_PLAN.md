# Рефакторинг «содержимое — подключаемыми модулями» (ветка `refactor/plugins`)

## Цель

Любая вещь игры добавляется **одним файлом** (плюс, по желанию, файлом отрисовки) без правок ядра, как это уже сделано для боссов в 2.6:
- оружие;
- инструмент;
- навык нити;
- оберег;
- приём;
- враг;
- снаряд;
- звук;
- арена.

Поведение игры не меняется. Проверка — после каждого шага:
- эталонные записи `tests/golden/v2` (хэш мира каждые 300 тиков);
- фаззер;
- юнит-тесты;
- сборка.

## Отраслевые практики, на которые опираемся

- **Тип-объект** (Nystrom, *Game Programming Patterns*): вид вещи — объект-описание с данными и хуками, а не ветка `if (id === …)`.
- **Реестр с автообнаружением**: файл в папке появляется сам. В Vite это `import.meta.glob`, в Node — чтение папки. Порядок задаётся явным полем `order`, а не случайным порядком файлов, иначе меняется детерминизм.
- **Хуки и события вместо вставок в ядро**: обереги, приёмы и реакции врагов подписываются на точки расширения (`hitEnemy`, `silkGain`, `dashCd`…). Ядро только вызывает эти точки в заданном порядке.
- **Модульные фичи** (Unreal Game Features): логика (`src/content`) и отрисовка (`src/view/content`) лежат раздельно. Ядро не знает об отрисовке, отрисовка видит ядро только через типы.
- **Проверка данных при загрузке** (zod): ошибка в описании — это ошибка запуска с понятным текстом.
- **Сеть и сохранения**: числовые коды на проводе задаются в описании явно (`netId`) и только добавляются. Реестр проверяет, что они уникальны.

## Устройство

```
src/core/plugin/registry.ts    общий реестр: define / get / ids (по order) / record (живой объект в порядке order)
src/content/<вид>/<id>.ts      описание вещи (default export defineX({...}))
src/content/index.ts           автозагрузка всех видов (glob / папки)
src/view/content/<вид>/<id>.ts отрисовка, иконка HUD, звуки вещи
```

Правило импорта для `src/content/**`: можно импортировать модули ядра, но только для вызова внутри функций. На верхнем уровне файла — только `defineX({...})`. Ядро не импортирует конкретные файлы содержимого.

## Порядок работ (каждый пункт — отдельный коммит, зелёные проверки)

0. Каркас: реестр, автозагрузка, правило линтера.
1. Оружие: описания и отрисовка удара, позы, заряда; высота тона заряда; особые эффекты заряда (булава).
2. Инструменты и навыки нити: описание, сущности (шаг, сеть, отрисовка), иконка HUD.
3. Обереги: точки расширения вместо `hasCharm` в ядре.
4. Приёмы набора (теневой рывок, вспышка, кристальный рывок, контрудар): шаг с явным приоритетом, коды для сети, HUD, отрисовка.
5. Враги: создание (тот же порядок вызовов ГСЧ), шаг, реакции на удар и инструменты, сеть, отрисовка.
6. Снаряды: шаг, флаги (прочный, тяжёлый, рубится), сеть, отрисовка; список видов для данных боссов строится из реестра.
7. Звуки: реестр звуков вместо `switch`; неизвестное имя — предупреждение в консоль.
8. Арены и главы: реестр арен вместо `enum` и полей `L.misha/vladik/tima`.
9. Документация `docs/CONTENT_HOWTO.md`: «как добавить X за 10 минут»; проверка `content:check`.

## Что остаётся замороженным

- Наблюдение нейросети (`src/agent/obs.ts`): фиксированные списки видов связаны с весами модели. Новые виды попадают в слот «прочее».
- Формат журналов и `.ttrec`: строки режимов и id не меняются.
