# Геймплей и движок: аудит перед следующими боссами

Проверка исходников от 23.10.2026. Новый босс не добавлялся. Основание — код текущего проекта и статический аудит установленного Silksong 1.0.30000. Вместимость расходников и правила отмен ниже — решения для Тропы Ткачей, не извлечённые численные параметры Silksong.

## Что уже достаточно развито

- Детерминированное ядро с шагом 60 Гц, отдельные потоки RNG, повтор ввода, копия мира для бота. Phaser отвечает за отображение.
- Пять оружий уже имеют разные геометрию, воздушные цепочки, финишеры, заряженные удары, отбрасывание и получение шёлка. Поэтому новый слой с теми же различиями под названием crest не нужен.
- Есть прыжок с буфером/coyote time и изменяемой высотой, стены, уступы, планирование, пого, двойной прыжок, теневой и воздушный рывки, кристальный разгон, контрудар.
- Есть отдельные отбив, лечение, всполох, прерывание действий уроном, проверка траектории вражеских снарядов и контракты урона/уязвимой точки.
- Содержимое подключается через реестры; ядро и графика разделены. Есть проверки честности, проходимости без урона и детерминизма.

## Исправлено в этом этапе

1. Три назначения инструмента: основной, вверх, вниз. Пустой направленный слот использует основной, конфликт ↑↓ выбирает нейтральный. Направление поддерживает диагонали и бросок вниз; бомба учитывает его физически. Слоты сохраняются, фильтруются по открытым предметам, передаются в позе напарника, видны в меню и HUD. Сенсорная кнопка доступна и когда заполнен только направленный слот.
2. Иглы/капканы/бомбы отделены от навыков на шёлке: запас 6/3/3, цена шёлком 0. Подбор иглы возвращает заряд. Отдых, новая сцена и возрождение дают полный запас. Один предмет в разных слотах использует общий запас. Перестановка снаряжения не пополняет заряд и не сбрасывает перезарядку. Навыки духа, нырка, вопля и крюка сохраняют прежние ресурсные правила.
3. Инструмент запрещён во время удара и его восстановления, рывка, лечения, урона, казни, управляющего движением приёма, посадки и отдыха. Отклонённая команда ничего не расходует. Это сознательное правило текущей боевой системы; автоматического буфера инструмента пока нет.
4. Сброс боя очищает старые сущности инструментов, чтобы бомба прошлого захода не ранила нового босса.
5. Запись хранит версию правил. Архив без gameplay использует прежнюю стоимость и ограничения инструментов. Новые сегменты используют gameplay=2. Сохраняются начальное снаряжение, смена набора и результат траты бусин при покупке. Контроль hv=3 дополнительно учитывает слоты, боеприпасы, cooldown и скалярное состояние сущностей инструментов. Это расширение, не полный снимок всего мира.
6. Исправлены ширина и компоновка меню снаряжения на узком экране. Подсказки и выбранный слот доступны без отладочных терминов.

## Что ещё нужно движку — порядок работ

| Приоритет | Пробел, подтверждённый кодом | Зачем и критерий готовности |
|---|---|---|
| P0 | Развитие существующих сущностей арены для эффектов босса | arena.ts уже хранит независимые зоны/лучи и часы мира. Столпы Сосуда пока остаются в active тела. Следует расширить существующую систему многоугольниками, экземплярами эффекта и серийным id атаки, сохранив правила отмены при смерти/оглушении. Проверка: босс начинает новый замах, прежний эффект продолжает наносить урон только в своём окне |
| P0 | Универсальные переходы FSM по событиям | Сейчас исполнитель в основном движется по кадрам; waitForGround — частный случай. Нужны явные условия «приземление», «контакт со стеной», «завершение логического клипа», «сигнал дочернего объекта». Анимация не должна управлять уроном таймерами Phaser |
| P0 для онлайна | Боссы на данных не входят в сетевой снимок | Вход в такие бои по сети намеренно закрыт. Нужны состояние/фаза/serial, RNG-решения хоста, независимые опасности, восстановление после пропуска событий, проверка двух клиентов. До этого обещать кооператив новых боссов нельзя |
| P1 | Матрица допустимых отмен для всех действий | Общий canStartAction покрывает часть системы; базовые атака/рывок и специальные движения ещё распределены по модулям. Нужна явная таблица состояний и регрессионные проверки каждого перехода. Сохранить нынешнюю отзывчивость прыжка и рывка |
| P1 | Сериализуемые отложенные события | World.after хранит callback; cloneWorld убирает tmr. Для будущих независимых атак это мешает точному прогнозированию и сохранению середины боя. Нужна очередь «тик + тип события + данные», а не замыкания |
| P1 | Общий бой при смене профиля оружия | Оружие уже различается, но доступные направленные/воздушные состояния и отмены стоит описать явно в WeaponDef. Нужны тесты всей матрицы оружие × босс × фаза, а не только базовой иглы |
| P1 | Подтверждение расхода инструмента хостом | Сейчас гостевые tool-события создают сущности у хоста; ресурс живёт у владельца. Для устойчивого кооператива нужны номер команды, подтверждение/отказ, согласование заряда и защита от повторной доставки. Текущая передача запасов в позе не заменяет эту задачу |
| P1 | Сброс тренировки как событие записи | Смена снаряжения теперь записывается; trainReset пока выполняется напрямую. Сейчас тренировки приложением не записываются, но для полноценного секвенсера это потребуется |
| P2 | Полный контроль состояния повтора | hv=3 закрывает инструменты, но ещё не все вложенные ссылки/наборы поражённых целей, RNG и очередь таймеров. Нужен версионированный канонический снимок боевого состояния |
| P2 | Спринт/торможение и сложный downspike | Отдельного спринта с правилами отмен нет. Вводить после замеров дистанций арен; новая скорость и диагональный удар могут обесценить существующих боссов. Базовый пого уже есть |
| P2 | Тестовый стенд качества ощущений | Нужны покадровая перемотка, фиксированная последовательность атак, скорость 25/50/100%, траектория героя, отметки input→действие→попадание. Это полезнее ещё одного нового босса до стабилизации основы |

## Что переносить из Silksong дальше

Сначала правила оружия и ресурса, затем движения. Конкретные числа скорости, кадры отмен, урон/цена каждого инструмента и FSM боссов пока не подтверждены живым оригинальным боем. FsmMaster и статическое чтение помогают получить эти данные, но сами по себе не переносят механики.

Практический следующий этап: независимые опасности + события FSM, затем завершение Focus/Tendril/Teleport у Сосуда, затем матрица оружия и отмен. После этого возвращаться к следующим боссам. Арены, анимации и звук проверять на той же временной шкале; наличие красивого эффекта не считается доказательством правильного попадания.
