# Уровни «Тропы Ткачей» в LDtk

Все уровни игры лежат в одном проекте **`levels/tropa.ldtk`** (формат LDtk 1.5.3, JSON). Это те же уровни, что были в v1.8, тайл в тайл:

| Идентификатор | Что это | Размер, клеток |
|---|---|---|
| `Ch1` | Глава I «Мшистая Глубь» (с ареной Корнематки) | 240 × 40 |
| `Road2`, `Road3`, `Road4` | коридоры перед аренами глав II–IV | 72 × 22 |
| `ArenaMisha` | арена Миши Додика («Старая типография») | 44 × 22 |
| `ArenaVladik` | класс Владика Скрипки (тема `class`) | 44 × 22 |
| `ArenaTima` | берлога Тимы Пива (тема `den`) | 44 × 22 |

Клетка — 32 px, как в игре. Все координаты в уровне — в клетках.

## Как открыть

1. Скачайте LDtk (бесплатно, Windows/macOS/Linux): <https://ldtk.io/> (версия 1.5.3 или новее; прямая ссылка на релизы — <https://github.com/deepnight/ldtk/releases>).
2. `File → Open…` → `levels/tropa.ldtk`. Уровни — на карте мира и в списке слева: `Ch1`, `Road2` …

## Что где лежит

**Слой `Tiles` (IntGrid)** — клетки карты. Пусто (нет значения) — воздух.

| Значение | Имя | В ядре |
|---|---|---|
| 1 | `Solid` — твёрдый (стены, пол, потолок) | `SOLID` |
| 2 | `Plat` — платформа (проходима снизу, на неё можно встать) | `PLAT` |
| 3 | `Spike` — шипы | `SPIKE` |

**Слой `Entities`** — сущности (всё, что лежит на карте). Позиция — клетка; у «растягиваемых» сущностей размер тоже в клетках.

| Сущность | Поля | Значение |
|---|---|---|
| `Spawn` | — | точка появления героев (обязательна, одна) |
| `Exit` | — | выход из уровня (нет в аренах) |
| `Bench` | — | скамья |
| `Sign` | `text`, `touch` | табличка; `touch` — текст для сенсорного управления (можно пусто) |
| `Enemy` | `type` | враг: `crawler`, `gnat`, `beetle`, `spitter`, `shell`, `lurker`, `bats` |
| `Item` | `ability`, `text` | предмет способности |
| `GateIn`, `GateOut` | — | ворота арены Корнематки; тяните по высоте: сколько клеток — такие ворота |
| `BossArena` | `arenaX0`, `arenaX1`, `trigger`, `floorY` | арена и триггер босса главы I; клетка сущности — где появляется босс |
| `Area` | `name` | с этой клетки X и правее показывается название области |
| `Crate` | — | ящик с дымовухами (арена Миши) |
| `Misha`, `Vladik`, `Tima` | — | позиция босса в арене |
| `Window`, `Curtain` | — | окно / штора класса; тяните по ширине (клетки X0…X1) |
| `Furniture` | `kind` | мебель берлоги: `couch`, `shelf`, `crates`; тяните по ширине. Платформы мебели **ещё и** нарисованы значением `Plat` в слое `Tiles` — правьте оба |

**Поля уровня** (панель справа при выбранном уровне): `region`, `theme`, `road`, `ceilY`, `floorY`, `noGates` (арена без ворот). Пустое значение — «не задано».

Порядок сущностей одного вида в слое имеет значение (например, порядок врагов в списке). Новые сущности LDtk добавляет в конец — этого достаточно.

## Как поправить

- **Тайл**: слой `Tiles` → выберите значение (1/2/3) или стёрку → рисуйте. Сохраните (`Ctrl+S`).
- **Сущность**: слой `Entities` → выберите сущность справа, поставьте или перетащите; поля — в панели справа.
- Загрузчик (`src/core/ldtk.ts`) при ошибке в файле пишет по-русски, что и где не так: «LDtk, уровень «Road2», сущность Sign (клетка 4, 17): «поле text» должно быть строкой…».
- Игра читает файл при сборке: `npm run dev` подхватит правку сразу, `npm run build` положит её в `index.html`.

> **Важно (v2.0).** Пока идёт перенос, действует правило «поведение игры не меняется»: тест `tests/unit/levels.test.ts` сверяет файл с кодом v1.8 и с генератором, и любая правка уровня его **намеренно ломает**. Когда придёт время менять уровни по-настоящему (после релиза 2.0), правьте в LDtk, а в тесте обновите эталон: уберите проверку против `tests/oracle/levels-code.ts` для изменённого уровня и против `legacy/` — либо перенесите изменение в оракул и запустите `npx tsx tools/ldtk-export.ts`. Золотые записи (`tests/golden`) от уровней зависят: изменённый уровень нужно записать заново.

## Как проверить

```
npm run levels:check
```

Команда перегенерирует `levels/tropa.ldtk` во временную папку, сравнивает с файлом в `levels/` (ловит ручную порчу) и запускает `tests/unit/levels.test.ts`:

- загрузчик → `Level` ядра строго равен кодовому оракулу `tests/oracle/levels-code.ts` (прежним построителям);
- и равен настоящему коду v1.8 из `legacy/src` (его выполняет Node через `vm`): сетка тайл в тайл, затем все сущности, таблички, враги, ворота, области;
- ошибки в файле (лишний тайл, неизвестная сущность, пустое поле…) дают понятное сообщение.

Остальное, как обычно: `npx vitest run` (золотые записи), `npx tsc --noEmit -p .`, `npx eslint .`, `npm run build`, `npm run sim -- --boss misha --frames 3000`.

## Как добавить уровень

1. В LDtk: правый клик по пустому месту карты мира → создать уровень. Задайте размер, кратный 32 px. Слои `Tiles` и `Entities` появятся сами. Дайте идентификатор латиницей (`Road5`).
2. Нарисуйте тайлы, поставьте `Spawn` (обязательно) и остальное.
3. Подключите в коде: добавьте идентификатор в `LEVEL_IDS` и функцию в `src/core/levels.ts`, а там, где уровень нужен (кампания, мир), вызовите её.
4. Если для уровня нужен тест на совпадение — добавьте его в `projectLevels()` генератора и построитель в оракул; для совсем нового уровня достаточно проверить его загрузку (`levelFromLdtk(tropa, 'Road5')` не бросает ошибок).

## Как устроено

- `src/core/ldtk.ts` — чистая функция «объект проекта LDtk + идентификатор уровня → `Level` ядра» (без fs/fetch), проверка входа.
- `src/core/levels.ts` — `buildLevel`, `buildRoad`, `ARENAS`: импортируют `levels/tropa.ldtk` как JSON (`import … with { type: 'json' }`) и вызывают загрузчик. Каждый вызов даёт новый объект.
- Подключение `.ldtk` как JSON: в Vite/Vitest — плагин `ldtk-json` в `vite.config.ts`; в Node/tsx — `tools/ldtk-register.mjs` (`npm run sim` подключает его сам; для своих скриптов: `tsx --import ./tools/ldtk-register.mjs файл.ts`).
- `tools/ldtk-export.ts` — генератор файла из кодового оракула (`npx tsx tools/ldtk-export.ts`, ключ `--out <папка>`).
- `tests/oracle/levels-code.ts` — прежние кодовые построители v1.8; в игровой бандл не попадают.
